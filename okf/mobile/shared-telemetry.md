`session.ts` implements the **session_id** ubiquitous-language term: a rotating correlation id grouping a search arc (search → click → play) so server-side session-signal derivation (abandoned-search, pogo-sticking — see [telemetry](../backend/discovery/telemetry.md)) can reason over query chains. `SessionState = { sessionId, lastActivity }`; the pure `advanceSession(state, now)` rotates the id (`makeSessionId`, a base36-timestamp + random suffix) after `SESSION_INACTIVITY_MS` (30 min) of inactivity — unit-testable with no RN dependency. The stateful wrapper (`_state` module-level variable) is a thin shell: `getSessionId()` calls `advanceSession` on every read, and `ensureForegroundRotation` (idempotent, guarded by `_listening`) registers an `AppState` listener that force-rotates on `active` regardless of inactivity, so every fresh app open starts a new arc. This split — pure logic function tested directly, stateful wrapper kept thin — is the pattern repeated in `outbox.ts`. The wrapper used to be documented as *untested because trivial*; the 2026-07-29 mutation audit killed that rule. By then the "trivial shell" had accumulated `flushOutbox`'s `_flushing` reentrancy guard, its commit-after-send ordering, its stop-on-first-failure backoff, and `outboxStore`'s empty/non-empty branch — and inverting `persistOutbox` so a non-empty queue *deleted* its file left the whole suite green. The module's strongest guarantee lived entirely inside the region the rule exempted from testing. Thin is still the goal; exempt is not.

`outbox.ts` implements the **two-tier reliability** term: `library_add` and `wrong_album` are label-critical (a lost event is a lost relevance label for the behavioral eval corpus, see [eval-harness](../backend/discovery/eval-harness.md)), so they route through `enqueueCritical` instead of firing directly. Each entry gets a client-minted `event_id` (`makeEventId`, an RFC4122-v4-shaped id — explicitly *not* a security token, so `Math.random` is acceptable) and a `client_occurred_at` timestamp (`withEnvelope`). The server dedups inserts on `event_id` (`ON CONFLICT … DO NOTHING`), making retry safe. `flushOutbox` drains the in-memory `_queue` (capped at `MAX_ENTRIES = 50` via `capEntries`, deduped by `dedupeById` keeping the last entry per id), stopping at the first *retryable* POST failure and leaving the remainder for the next trigger — either another `enqueueCritical` call or an `AppState → active` transition (`ensureFlushOnForeground`). A **400 is not retryable and drops the entry** instead of stopping the drain, because the server will never accept that payload and a retained one blocks everything behind it: the loop's `catch` is a `break`, so before 2026-07-31 a single permanently-rejected entry sat at the head of the queue forever and no `library_add` or `wrong_album` queued after it could ever be delivered. That was live — every save without a `result_signature` sent `result_signature: null`, which `validatePayloadTypes` 400s (see [telemetry](../backend/discovery/telemetry.md)) — so the label-critical tier, the one thing this module exists to guarantee, was bricked by its own producers. The classifier is deliberately narrow: only `ApiError(400)` drops. A 401 is *retried*, because `apiFetch` throws 401 whenever the Supabase session is momentarily absent, and dropping on that would invent a new loss path in the tier the outbox protects. The queue **is** mirrored to disk and does survive a hard app-kill: `outboxStore.ts` writes it as a JSON file through `expo-file-system` (an existing dependency — no new native module, so no ADR was needed), and `loadPersistedOutbox` filters out entries without a **non-empty** string `event_id` so a partial write can't poison the flush loop. The non-empty half was added 2026-07-31: `''` is a valid `string` but not a usable id, and since `dedupeById` keys a `Map` on it, several empty-id entries collapse into one — silent loss of exactly the labels the filter exists to protect. The filter also drops corrupt elements individually rather than aborting: a stray `null` beside valid entries must not discard the whole backlog, which is what happens if the `e === null` half of the type guard is dropped, since `typeof null === 'object'` and the resulting throw escapes `.filter()` into the outer `catch`. Disk failures degrade to in-memory-only and never throw. (This paragraph claimed the opposite until 2026-07-30 — it predated `outboxStore.ts` and contradicted `src/shared/telemetry/CLAUDE.md`, which had the current behavior right.) The durable write itself (`createTrack`) is already server-side safe; this only protects the telemetry label. `_resetOutboxForTest` clears module state for tests.

`recordEvent.ts` is the behavioral `/events` send and its wire types (`DiscoveryEvent`, `DiscoveryEventType`). It POSTs `/v1/discovery/events` via `apiFetch` (from [shared-api-client](shared-api-client.md)) and stamps the rotating `session_id` (`getSessionId` from `session.ts`) onto every event's JSONB payload, so call sites never thread it. It lives here — not in `api-client/discovery.ts` where it used to — because it is telemetry, not a search call: keeping it in api-client made the base HTTP layer import *up* into telemetry while `outbox.ts` imported back down (a two-way subsystem dependency, structure audit F1). The direction is now one-way: telemetry → api-client.

`outboxFile()`'s `if (!dir.exists) dir.create({ intermediates: true })` guard is load-bearing, not defensive: `expo-file-system`'s `Directory.create()` **throws when the directory already exists** unless `idempotent: true`, which this call does not pass. Without the guard every call after the first throws inside `outboxFile()`, is swallowed by the surrounding `catch`, and the whole outbox goes permanently inert — nothing persists, nothing loads, no error anywhere. Nothing constrained that until 2026-07-31, because the `expo-file-system` double modelled `create()` as an idempotent set-add; the double now throws to match the native contract, which makes the same guard load-bearing at all five of its call sites across the app (`pinnedFiles`, `pinnedStore`, `audioPrefetch`, `themePreference`, here).

`useRecordEvent.ts` is the shared entry point for *everything else* — a `useMutation` wrapping `recordEvent` (from `./recordEvent`) fire-and-forget, swallowing errors to a `console.warn` per ADR-0007 §3.12 ("telemetry is best-effort, never surfaced to the user"). It replaced a legacy per-feature `useRecordClick` + `/clicks` endpoint; now one hook serves `results_shown`, `result_clicked`, `play`, `skip`, `completed` across discover, detail, and playback — `library_add` and `wrong_album` are label-critical and take the outbox instead, an invariant now asserted against the feature tree rather than left to caller discipline. Swallowing to `console.warn` is what let two live wire defects run unnoticed: `results_shown` was rejected as server-reserved for eight days, and every `result_signature: null` 400'd. Best-effort means the *user* never sees a failure; it does not mean nobody does. The contract test now derives the accepted type set and the payload type constraints from Go at test time, so the next such drift fails CI instead of accumulating in a log nobody reads.

Consumed by discover, track-detail, and playback UI wherever a behavioral event fires.

**Durability (2026-07-24).** The critical outbox now mirrors to `Paths.document/telemetry/critical-outbox.json` (`outboxStore.ts`) and restores on first use, so a hard app-kill while offline no longer loses queued labels — the exact events the outbox exists to protect. The documented blocker was "needs a durable client store (AsyncStorage / SQLite), which is not a current dependency"; `expo-file-system` already is one (the audio prefetch cache uses it), so this costs no new native module and no ADR. Restore is lazy rather than at import time, since module init runs during bundle evaluation before the app has decided it needs telemetry. Every disk operation is best-effort: a failed write degrades to in-memory-only and never throws into a caller.
