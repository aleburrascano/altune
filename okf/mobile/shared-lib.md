Everything here is a pure module promoted on its second consumer. `query-keys.ts` — `libraryKeys`/`playlistKeys`, the React Query cache topology's single declaration; the feature hooks and the SSE patch layer (`@shared/events`) import the same builders instead of retyping key literals (added by the 2026-07-16 library structure audit after the retired `['library']` key survived its deleted hook in five files). `async-view.ts` — `asyncView` encodes the one shared precedence rule *loading > error > empty > ready*; the [library](library-feature.md) and [discover](discover-feature.md) `state.ts` each wrap it with their own definition of what counts as loading/empty. `derive-library-groups.ts` — `deriveAlbums`/`deriveArtists` fold a `TrackResponse[]` into `AlbumGroup`/`ArtistGroup` (UI read-side lenses, not domain types) via one shared `deriveGroups` fold (track count, most-recent `added_at`, first-available artwork); used by library grouping and the [detail](detail-feature.md) artist screen. `featured.ts` — `featuredArtistsFromExtras` parses the `featured_artists` extras key (also accepting bare-string names as id-less credits, though **no producer on either surface emits that shape** — see below) and `withFeaturing` renders the comma-joined co-billed credit ("Ken Carson, Playboi Carti"); used by library/discover rows, detail, and all three playback player surfaces. `format.ts` — `formatDuration` (m:ss); library rows and detail extras. `track-to-discovery.ts` — `trackToDiscoveryResult` adapts a saved library `TrackResponse` into the discovery wire shape so a saved Track flows through the same handoff path as a search result; used by library navigation and detail's album/artist/lateral navigation.

The one real invariant lives in `detail-handoff.ts`: it is the **in-memory seam between discover and detail**. Discover (and library, via `trackToDiscoveryResult`) stashes the tapped `DiscoveryResult` plus its originating `search_id` (so downstream engagement telemetry — library_add, play — can join back to the search) and navigates; `DetailScreen` reads it on mount instead of doing a per-item backend fetch. A cold start (deep link, reload) leaves the handoff null and detail redirects to `/discover`. It sits in shared/ because it has a writer (discover, library) and a reader (detail) in different features — it cannot be a cross-feature import.

**`isNetworkError.ts` (2026-07-24).** The transport-failure classifier promoted out of `features/auth/lib/` on its second consumer. Library and Discover use it to tell "you are offline" from "the server failed" in their error copy; auth additionally maps `'network'` to distinct wording. The heuristic is knowingly approximate — one regex over the error message — but it is the only connectivity signal available without NetInfo, which is a native module and would need a new dev build.

**`query-keys.ts`** also now owns `discoveryKeys`, promoted out of `features/discover/keys.ts` when Settings gained "Clear search history" and needed `discoveryKeys.history` to invalidate after the server delete. A shared home beats a cross-feature import, and this file already declares itself the single declaration of the cache topology.

## `derive-library-groups.ts` is gone (2026-07-25)

`deriveAlbums` / `deriveArtists` folded a `TrackResponse[]` into album and artist groups on the device. Both are now SQL `GROUP BY`s behind `/v1/library/albums` and `/v1/library/artists`, and the group types live in `@shared/api-client/library` as wire types (see [library-feature](library-feature.md)).

`query-keys.ts` changed shape with it: `libraryKeys.home` is replaced by four families — `tracks(query, sort)`, `lookup(query)`, `albums(query, sort)` and `artists(query, sort)` — each with a prefix for the SSE patch layer to sweep.

## `libraryKeys.summary` (2026-07-25)

A fifth family beside the four query-keyed ones: a single cache holding a `limit: 1` track response, used only to answer "does this user own anything at all" for the library's empty-state CTA.

It is deliberately **not** under `tracksPrefix`. The SSE patch layer sweeps that prefix treating every entry as `InfiniteData`; a flat `ListTracksResponse` there would fail on the first patch. Being a separate key also means it is invalidated rather than patched, which is correct — it is a property of the whole collection, not of any row.

## What the 2026-07-31 rebuild changed (slice 6)

Three source defects, all found by deriving intended behaviour from the source rather than by any coverage or mutation number. Full record: [shared-lib](../testing/shared-lib.md).

**`formatDuration` did not clamp a negative duration.** JavaScript's `%` returns a negative remainder and `Math.floor` rounds toward `-Infinity`, so `formatDuration(-5)` rendered the literal string `-1:-5` — and `padStart(2,'0')` never fired, because `"-5"` is already two characters. Two of the four call sites (`AlbumTrackRow`, `ArtistDetailBody`) guard only against `null`, and `trackExtras` filters non-finite values but not negatives, so a negative `duration_seconds` on the wire reached the formatter unimpeded. Now `Math.max(0, …)`, so a nonsense duration renders `0:00`.

Deliberately **not** guarded: `NaN` and `±Infinity`. The parameter is typed `number`, JSON cannot carry either literal, and `trackExtras` already rejects non-finite values — so four `it.failing()` markers proposed for them were **rejected** rather than committed. A marker nobody can ever promote is noise the next person deletes, and guarding an unreachable input is error handling for an impossible scenario.

**`featuredArtistsFromExtras` admitted a non-finite `deezer_id`.** The guard was `typeof rec['deezer_id'] === 'number'`, and `typeof NaN === 'number'`. This one *was* fixed rather than rejected, and the distinction from the `formatDuration` case is the point: this function's parameter is `unknown` and its entire job is to narrow untrusted wire data, so admitting a value it cannot validate contradicts its own contract regardless of whether a producer currently emits one. `Number.isFinite` now backs the `typeof` check.

**`trackToDiscoveryResult` passed an empty `artwork_url` through as an image URI.** It used `?? null`, which only collapses `null`/`undefined`, so `artwork_url: ""` survived into `DiscoveryResult.image_url`. `Artwork` renders `source={uri != null ? { uri } : null}` — an empty string is *not* null, so the UI issued a request for an empty URI instead of drawing its placeholder. The Go side makes this reachable: `TrackDTO.ArtworkURL` is a raw `*string` passthrough, unlike `Album` which is explicitly normalised from `""` to nil in the same function. Now `|| null`. This was the run's only mutation survivor, and the fix is scoped to this slice — `Artwork` treating `""` as a live URI is a `shared/ui` concern and is recorded as such.

**Two dead regions were surfaced and deliberately kept.** `clearDetailHandoff` has zero production callers — but that is documented and accepted in [ADR-0017](../../docs/adr/0017-detail-handoff-module-state.md), which states the handoff is cleared implicitly by the next write and that the cold-start `null` → `/discover` redirect covers the one case that matters. The bare-string arm of `featuredArtistsFromExtras` likewise has no producer: every Go path routes through `domain.FeaturedArtistsToExtras`, which emits `[]map[string]any`, and migration `010_track_featured_artists.sql` was relational from introduction, so there is no historical wire shape it guards either. Both are tested, neither is deleted; deletion is the owner's call.

**A tearing hazard, recorded rather than fixed.** `_lastTapped` and `_searchId` are two independent module variables with no atomic pairing, so a write landing between the two getters yields a mismatched pair — track A attributed to search B in `library_add` telemetry. It does not manifest today: the only two-read call site, `useSaveTrack`, reads both with nothing but synchronous statements between them. Inserting an `await` between those two lines would silently produce mis-attributed telemetry with no error. The test asserts the invariant that *does* hold (both readers observe the same write when nothing writes between them) rather than asserting the hazard, so a future fix that merges the two variables into one record keeps the suite green instead of turning it red.

**`libraryKeys.tracksAll` and `discoveryKeys.favorites` (2026-08-02).** Two keys added. `tracksAll(query, sort)` → `['library','tracks','all',query,sort]` caches the whole-collection fetch behind library playback; it sits under the existing `tracksPrefix`, so every invalidation that already targets library tracks reaches it too — that is the point of nesting it there rather than giving it a sibling root. It cannot collide with `tracks('all', sort)`, which is one element shorter. `favorites` → `['discovery','favorites']` is a singleton, not a factory: the list is per-user and unparameterized.
