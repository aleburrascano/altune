`internal/shared/` holds cross-cutting, framework-adjacent utilities the hexagonal contexts all depend on (per [backend/index.md](index.md), this is the one layer domain code may import from besides stdlib). **config** (`config.go`): a single `Config` struct loaded via `caarlos0/env` + `godotenv`, with `env:"..."`/`envDefault:"..."` tags for every setting. `Load` reads the dotenv file by explicit name — `godotenv.Load(".env.development")`, not the library's default `.env` — so the dev file's name declares its scope alongside `.env.production`; the error is discarded because production has no dotenv file at all (Compose injects it via `env_file`) and the relative path only resolves when the process runs from `services/go-api` (DB/Redis URLs, Supabase JWT/JWKS, provider API keys, feature flags like `TailDemotionEnabled`, `BehavioralRankingEnabled`, `ExplorationEnabled`/`ExplorationRate`, `IdentityVerifyOnPersist`). The identity-first V2 detail path is no longer flag-gated — its `DetailIdentityFirst`/`DiscographyV2` flags were **removed** 2026-07-23 now that V2 is the sole detail path (it activates whenever the artist-content service has an identity store; see [app-wiring](app-wiring.md)). `validate()` fails fast if `SUPABASE_JWT_JWKS_URL` is unset. `LogValue()` implements `slog.LogValuer` to redact secrets, logging only booleans (`has_redis`, `has_lastfm`, etc.).

**database** (`database.go`): `NewPool` wraps `pgxpool`, pinging once at startup and **erroring when `databaseURL == ""`** — the database is required (unlike Redis), so an unconfigured URL fails startup instead of handing repositories a nil pool that panics on first query (structure-audit F2, 2026-07-16; callers wanting a "not configured" report check `cfg.DatabaseURL` themselves, as `health_check.go` does). **redis** (`redis.go`): `NewClient` returns `nil` only when the URL is empty/invalid; a ping failure is logged as a warning (`slog.Warn`) but the client is still returned (non-nil, network-unreachable) — so downstream cache adapters must tolerate failing Redis calls, not just check for a nil client, when Redis is configured but unreachable (see [cache-layer](discovery/cache-layer.md)).

**logging** (`logging.go` + `ringbuffer_handler.go`): `Setup(logLevel, development)` takes the two values it needs (not `*config.Config`, so logging has no intra-shared dependency) and installs either a custom color `prettyHandler` (dev; renders `WithGroup` groups as dot-joined key prefixes) or `slog.NewJSONHandler` (prod) wrapped in a `ringHandler` that tees every record into a `RingBuffer` (fixed capacity `logRingCapacity = 1000`, capture floor `slog.LevelDebug` regardless of stdout's level) feeding the Mission Control logs panel (see [admin](admin/index.md)); `Subscribe` gives a lossy live-tail channel (`fanOutDroppingWhenSubscriberIsFull` drops for slow subscribers, never blocking the logger); `flattenedAttrs` builds the captured copy before the ring's mutex is taken.

**httptrace** (`recorder.go`/`replay.go`): `Recorder` is a debug-only `http.RoundTripper` that buffers full request/response bodies per exchange (never for production traffic); `Replayer` answers requests from previously recorded `Exchange`s matched on `(method, URL, body)` in FIFO capture order, erroring loudly on an unmatched request — enables deterministic offline discovery-eval reruns (see [eval-harness](discovery/eval-harness.md)).

**httputil** (`errors.go`/`middleware.go`): `StatusError` interface (`error` + `HTTPStatus() int`) satisfied structurally by domain errors so `domain/` never imports `net/http`; `HandleServiceError` is the single domain-error→HTTP translation point. Middleware: `CorrelationID` (stamps an 8-char id via context + response header), `RequestLogger`, `Recoverer` (panic recovery → structured log + 500), `MaxBodySize`.

**textnorm** (`normalize.go`/`fuzzy.go`): `NormalizeForMatch` canonicalizes titles/names (NFKC → lowercase → strip diacritics → drop bracketed suffixes → `&`→"and" → strip apostrophes → Unicode-aware symbol stripping via `stripSymbols`, whose `isWordContent` / `isASCIIWordChar` / `isASCIIWhitespace` predicates preserve non-ASCII letters and numbers, e.g. CJK — `internal/shared/CLAUDE.md` records the past bug where the old ASCII-only `\w` regex zeroed out CJK titles). `TokenSortRatio`/`LevenshteinDistance` in `fuzzy.go` implement rapidfuzz-style token-sort fuzzy matching for discovery dedup; `levenshteinRatio` normalizes by **rune** counts (2026-07-23 — the old byte-length denominator against a rune-counted distance scored CJK strings sharing zero characters ~0.67 similar; ASCII behavior unchanged).

**UserId** (`userid.go`): the canonical cross-context identity value object — unexported `uuid.UUID` field, `NewUserId`/`ParseUserId` constructors, `UUID()`/`String()`/`IsZero()` accessors — used by every domain type (`Track.UserId`, `Playlist.UserId`, `QueueState.UserId`, etc.) per the domain-layer rule that shared value objects — plus the pure `textnorm` functions — are the only permitted domain-layer imports from `internal/shared/`. That rule is now lint-enforced: depguard (`services/go-api/.golangci.yml`, run in the test-backend CI workflow) fails the build if a `domain/` package imports any other shared subpackage or if anything under `internal/shared/` imports a feature.

## Text normalization

`stripSymbols` must stay Unicode-aware. The old ASCII-only `[^\w\s]` regex deleted every CJK and non-Latin letter — "坂本龍一" normalized to `""` and became unrankable, because an empty qnorm disables relevance. `isWordContent` keeps letters and numbers of any script while still dropping symbols and hyphens, and for ASCII input the output is byte-identical to the old regex. Matching is symmetric (query and title both pass through it), so keeping more letters cannot break a match. Keeping symbols — the artist `¥$`, the `07-The Best ...` hyphen-tokenization trap — remains an eval-matcher concern to fix in the matcher, not here.

`NormalizeForMatch` deliberately has no hand-curated word lists. A leading-article strip (the/los/les/el/la/le) and feature-token normalization (feat/ft/featuring/with) were removed in 2026-06: they were fit to the expected catalog languages, and the "with" rule mangled real titles like "Stuck with U". Both sides of a comparison keep their articles, so matching is unaffected.

`stripDiacritics` recomposes to NFC after dropping combining marks. That is a no-op for Latin bases, but it recomposes decomposed scripts like Hangul from jamo back to syllables, so the output is canonical rather than jamo-decomposed.

## Logging ring buffer

The ring captures at Debug (`ringCaptureFloor`) regardless of stdout level, so the operator console keeps rich provider and breaker DEBUG lines even when production stdout runs at INFO; `Handle` forwards to stdout only when stdout's own level wants the record, so those lines are not also printed. `CapturedRecord` is a flattened copy — the originating `slog.Record` is never retained, because its `Attrs` are unsafe to read after `Handle` returns — and `flattenedAttrs` builds the copy before `append` takes the ring's mutex, so the inner handler's formatting lock is never held across the ring's. The live-tail fan-out is lossy by design, like the SSE event bus: `fanOutDroppingWhenSubscriberIsFull` drops for a slow subscriber rather than blocking the logging hot path, and `logRingCapacity` is sized for a single-operator console on a memory-constrained box rather than durable retention.

## Event bus

`InProcessBus.users` grows one entry per distinct `UserId` and is never evicted — a few hundred bytes per user, bounded in practice by the family-scale user base, and reset on restart like all in-memory state. `idBaseMonotonicAcrossRestarts` seeds every user's counter from the wall clock at process start; without it the per-user `nextID` restarts near 0 (regression F5) and a client that had already seen low ids from the previous process would mis-dedupe or stop on reconnect. A later process always starts above the earlier one's range, pinned by `TestPublish_EpochSeedsEventIDs` and `TestPublish_LaterProcessHasHigherIDs`.

Delivery is lossy by design: `recordDropForFullSubscriber` drops rather than blocking `Publish`, because the ring plus `Replay` is the recovery path, and `Dropped()` makes that backpressure observable. `warnIfEventsWereEvictedBeforeResume` surfaces a resume landing after an already-evicted id — the client still receives only the retained tail, but a silent gap otherwise looks exactly like a clean resume. `afterID == 0` means "from the beginning" and expects no gap. `NoopPublisher` discards every event so callers without a real `Publisher` default to it instead of nil-guarding every `Publish`.

## HTTP error translation

`StatusError` is satisfied structurally: a domain or service error carries its own HTTP status and a client-safe message without importing `httputil`, keeping `net/http` out of the inner rings. `HandleServiceError` is the single translation point and replaced the per-handler `errors.Is`/`As` ladders — a `StatusError` in the chain renders with its declared status and message, anything else is logged and returned as a generic 500 so internals never reach the client.

`statusWriter.Flush` forwards to the underlying `ResponseWriter` so streaming handlers keep working through the logging wrapper: the SSE endpoint at `/v1/events` type-asserts `http.Flusher`, and without the forward that assertion fails and SSE 500s. `WithCorrelationID` exists for synthetic request paths — the Mission Control re-run inspector — that need correlation-keyed telemetry without passing through the HTTP middleware.

## Record/replay

`Recorder` is a debug and observability tool that buffers full response bodies in memory, so it belongs only in throwaway clients (the `discoverytrace` CLI, tests) and never on the production path; `RoundTrip` restores both request and response bodies so the caller is unaffected. `Replayer` is its other half: record once against live providers, then replay through the real pipeline for a deterministic offline run. Requests match on `(method, URL, request body)` — the fields a provider reconstructs deterministically from a fixed query and fixed credentials — and the body matters for POST/GraphQL providers whose query is not in the URL. Repeated identical requests replay in capture order so pagination and retries reproduce faithfully. A request with no matching exchange is a hard error rather than a silent empty response, so a missing fixture surfaces loudly and a deterministic eval can trust what it replayed; `Remaining()` reports exchanges never replayed, and a non-zero count means the replay diverged from the capture.

## Config flags

Auth is JWKS-only — HS256 is not implemented, matching the Python behavior `Load` replaced — and a missing `SUPABASE_JWT_JWKS_URL` is a hard validation failure. `SUPABASE_ANON_KEY` is the publishable key, safe to expose to browsers, and lets the Mission Control page sign the operator in with email and password directly. `OPERATOR_USER_ID` gates the console fail-closed: unset denies everyone. `ALERT_NTFY_URL` empty means alerts are logged only and never pushed, and the topic must be non-guessable. `ALERT_ZERO_RESULT_THRESHOLD` (0 disables) pages on 24h zero-result counts — aggregate only, never query text. `Config.LogValue` implements `slog.LogValuer` to redact secrets, reporting `has_*` booleans rather than values.

Ranking and eval flags, and why each default is what it is:

- `EVAL_METER_ENABLED` (off) — the live smoke run hits real provider APIs and shares per-provider quota with user traffic, so it must be opted into deliberately.
- `TAIL_DEMOTION_ENABLED` (off) — demotes single-source UGC/scrobble results with no identity below corroborated ones. Flipped on for eval A/B before any production rollout. See `docs/brainstorms/2026-06-27-discovery-tail-noise-demotion.md`.
- `CROSS_KIND_PROMINENCE_ENABLED` (**on**) — among equally relevant results of different kinds, the more prominent entity (Deezer `nb_fan`/rank, log-compressed) sorts first, fixing bare-name artist-intent burial without touching track-vs-track order. The 2026-06-29 fixture A/B proved artist-intent top-1 +7.8pp and track-hard top-3 +3.4pp (−38 obscure-artist-on-top failures) with track-exact byte-identical. See `docs/solutions/2026-06-29-cross-kind-ranking-ties.md`.
- `BEHAVIORAL_RANKING_ENABLED` (off) — feeds the EventConsumer-derived satisfaction signal (play-to-completion positive, skip-after-click negative) into ranking as a within-tie input. A new ranking consumer, so it ships dark until eval A/B proves it on the hard corpus.
- `BEHAVIORAL_CORPUS_PATH` (empty disables) — when set to a writable path, the nightly job materializes search-to-engagement labels plus `wrong_album` hard negatives into the eval corpus format.
- `EXPLORATION_ENABLED` (off) / `EXPLORATION_RATE` — serves a randomized result order for a small fraction of searches, logged as exploration, so offline counterfactual eval has unbiased propensity data. The one user-facing behavior change, shipped dark so it needs no live sign-off.
- `IDENTITY_VERIFY_ON_PERSIST` (off) — the permanent identity-bridge fix (`docs/discovery-detail-pipeline.md` §7). MusicBrainz url-relations are not always correct, and a wrong streaming link fuses two same-name artists (the wrong Deezer "Che"). When on, each learned streaming edge is checked against the artist's MusicBrainz release-groups before the bridge is persisted and a non-overlapping edge is dropped, so the durable identity and everything reading it never inherit the contamination. Runs off the request path; ships dark until its added fetch load is measured.

## `leader/` — one instance runs the background loops (2026-07-25)

`Election` wraps a Postgres **session-scoped** advisory lock (`pg_try_advisory_lock`) held on a connection checked out of the pool for the process lifetime. `IsLeader()` reports whether this process holds it; `Await(ctx)` blocks until it does. The composition root registers every periodic loop through `App.whenLeader` and starts them only after `Await` returns, so exactly one process runs the alert monitor, eval meter, vocabulary refresh, behavioural refresh, corpus refresh and metrics rollup.

Introduced for blue-green deploys (see [production-deployment](../playbooks/production-deployment.md)), where two versions are deliberately alive at once. Request handling is safe under that — Caddy routes to one colour — but the loops are not: the alert monitor's `firing` de-dup map is per-process, so a second instance re-notifies everything already firing, and four of the loops run once at boot, which on a 1-core VM means the standby competes for CPU with the health check that is deciding whether to promote it.

Two properties matter and both come from the lock being session-scoped rather than transaction-scoped:

- **It requires the session-mode pooler.** The Supabase URL uses port 5432. Over a transaction-mode pooler (6543) each statement may land on a different backend, so the lock is not reliably held across statements and `IsLeader()` would be fiction. This is why the `DATABASE_URL` port is an invariant, not a preference.
- **Release is automatic.** A crashed or killed process drops its connection and Postgres releases the lock; the standby's 10s retry picks it up. There is no lease to expire and no way to leave the jobs permanently unowned — which is what rules out the simpler alternatives (an env flag on the standby, or an admin "promote" endpoint): both fail silently closed, leaving nobody running the loops after an unlucky restart.

`verify` re-pings the held connection each tick and drops leadership if it died, so a half-open connection surfaces as a lost election rather than a leader that no longer holds anything. The acquisition scheduler is deliberately *not* gated — it is request-driven, not periodic, so it only acts on requests its own colour received.
