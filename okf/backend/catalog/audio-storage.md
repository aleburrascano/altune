`AudioStore` (`ports/audio_store.go`) is the port for reading/writing a track's audio file: `Exists`/`Store`/`Stream`/`Delete`, where `Stream` returns an `AudioStream` (`io.ReadSeeker` + `io.Closer` — the caller must close it). `AudioContentType(audioRef string) string` is the single audio-ref→MIME mapping (`.m4a`→`audio/mp4`, `.opus`→`audio/opus`, `.ogg`→`audio/ogg`, default `audio/mpeg` for legacy mp3 refs), shared by the upload side (object storage sets it on `PutObject`) and the serve side (`StreamHandler` sets the response header) — the two must agree because iOS/expo-audio decodes progressive audio by Content-Type, not by sniffing.

`AudioURLSigner` is an *optional* capability an `AudioStore` may additionally implement: `PresignGet(ctx, audioRef, ttl) (string, error)` mints a short-lived URL the native player streams directly from storage, bypassing the API proxy (which otherwise pays auth + Postgres + two storage round-trips per range request). Detected with a type assertion (`signer, _ := store.(ports.AudioURLSigner)`), never required — the filesystem store simply doesn't implement it, and callers fall back to the proxy stream endpoint.

Two adapters (`adapters/storage/`):
- **`FilesystemAudioStore`** (`filesystem.go`) — local disk under `baseDir`. `safePath` rejects any `audioRef` that isn't `filepath.IsLocal` (blocks path traversal). `Store` prefers `os.Rename`; on `syscall.EXDEV` (source temp dir and destination audio volume on different filesystems — the norm on a Linux VM with a separate mounted volume) it falls back to `copyThenRemoveAcrossFilesystems`. Does **not** implement `AudioURLSigner`.
- **`ObjectStorageAudioStore`** (`object_storage.go`) — MinIO/S3-compatible client. Implements both `AudioStore` and `AudioURLSigner`. `PresignGet` is a local HMAC-over-the-request operation (no network call to storage), so it's cheap enough to mint per track at queue-build time. `Store` sets `ContentType` via `ports.AudioContentType` on `PutObject`.

Services:
- **`AudioURLService`** (`audio_url.go`) mints presigned URLs (`audioURLTTL` = 1 hour) for a batch of tracks so the native player streams directly from storage. Constructed from an `AudioStore`; if the store doesn't satisfy `AudioURLSigner`, `signer` is nil and `Resolve` returns `(nil, nil)` immediately — every track falls back to the proxy. Otherwise: one `ListByIDs` batch read for the whole request (a narrow `trackBatchReader` interface) instead of a `GetByID` per track — per-id lookups here cost two queries per track on the hottest path after search (every queue build). A track that's unknown, not owned, or not `IsStreamable()` is silently skipped; a per-track presign failure (logged via `slog.WarnContext`) skips only that track, never the whole batch. `Resolve` times its two phases separately and logs them on `"audio_url.resolved"` (`db_lookup_ms` for the `ListByIDs` call, `presign_ms` for the per-track `PresignGet` loop, plus `requested`/`resolved` counts) — added for latency diagnosis, so a slow request can be attributed to Postgres vs. the presign loop instead of the batch as a whole. Each `ResolvedAudioURL` also carries the track's `AudioVersion` (see [track](track.md)), which is what lets a client tell whether a copy it already holds is the audio this URL now points at — the URL itself cannot answer that, since the presigned signature rotates on every resolve while the object key never changes. It is passed through verbatim as an opaque token: this service neither parses nor generates it, and an empty value (a track not acquired since migration 014) is forwarded as empty rather than substituted, because the client's "keep what you have" branch depends on telling absent from changed.
- **`StreamTrackService`** (`stream_track.go`) is the proxy path: `Execute` loads the track, checks `IsStreamable()` (else `ErrAudioNotAvailable`), and streams via `AudioStore.Stream`. On a storage miss it calls `recoverMissingAudio`, which re-checks `Exists` and — if genuinely gone — marks the track `Failed` (`track.MarkFailed`, persisted via `Update`) and unconditionally reschedules acquisition (fire-and-forget; scheduling runs whether or not the mark-failed persist succeeded). `RecoverIfMissing` is the separate entry point for *presigned* streams, which bypass `Execute` entirely (they hit storage directly) and so miss its safety net: the client calls it on a playback error, and it only acts when the object is genuinely absent — a transient network failure over a file that's actually present is a no-op, avoiding spurious re-acquisition. Both paths funnel into the shared `reconcileMissingAudio`, parameterized by an already-known `exists`/`err` so `RecoverIfMissing` (which already ran its own `Exists` check) doesn't pay for a second storage round-trip. `Execute` also splits its two I/O phases for latency diagnosis: on success it logs `"stream.opened"` with `db_lookup_ms` (the `GetByID` call) and `storage_open_ms` (the `audioStore.Stream` open, i.e. time-to-first-byte-available from storage) alongside `track_id`, so a slow proxy stream can be attributed to Postgres vs. the storage backend.

**Out-of-band audio and `cmd/backfillaudio`.** Both read paths gate on `Track.IsStreamable()` — `AcquisitionStatus == ready && AudioRef != nil` — *before* any storage call, so the bucket is never consulted for a track the database does not already claim is ready. That ordering is deliberate (it keeps a cold cache miss from turning into an S3 round-trip per unplayable track) but it has a sharp consequence: audio placed in storage out-of-band is invisible. Copying files into the bucket sets no row state, and `AudioRef` is written in exactly one place, the acquisition pipeline's Store step. A hand-imported library therefore stays `pending` forever and fails with `ErrAudioNotAvailable` while the bytes sit in the bucket untouched. The same gap explains a correlation that looks like two bugs: such tracks also have no artwork, because artwork is filled by the same pipeline that would have set the ref — "no artwork" is a visible proxy for "never acquired", which is the same set as "won't play".

`cmd/backfillaudio` closes it. For each track that is not streamable (optionally filtered by album — it defaults to `UNRELEASED`, the convention for hand-imported unreleased material — and by user), it derives the canonical key with the acquisition pipeline's own `BuildAudioRef` rather than a copy, tries it once per known container extension (`.mp3`, `.m4a`, `.opus`, `.ogg`, matching `AudioContentType`), and marks the track ready only on an `Exists` hit for that exact key. It never guesses: a miss prints every key it tried, which is also the diagnostic for a bucket whose layout does not match the pipeline's.

Two layouts coexist in the bucket and the tool tries both, in order. The pipeline writes `<userId>/<artist>/<album>/<title>.<ext>`; audio imported out-of-band lands at `<artist>/<album>/<title>.<ext>`, with no owner prefix — the same `BuildAudioRef` call with an empty `UserID` and the leading slash trimmed, so the sanitizer stays shared rather than forked. Two supporting read-only modes exist because *finding out what is actually in storage* turned out to be the hard part of the problem, not the writing: `-list` dumps every object key (via `AudioLister`, a narrow port detected by type assertion exactly like `AudioURLSigner` — the object store implements it over `minio.ListObjects`, the filesystem store does not, and the tool degrades with a clear error), and `-verify` inverts the candidate query to walk *ready* tracks and report any whose stored `audio_ref` no longer resolves. A ref that dangles is a track the library believes is playable and that will fail at the player instead. Writes go through `MarkReady` + `Update` like every other status change, and require an explicit `-apply` — the default run only reports.

Handlers:
- **`AudioURLHandler`** (`adapters/handler/audio_url_handler.go`) — `POST /audio-urls`, batch capped at `maxAudioURLBatch` (200) so one request can't sign thousands of objects; unsignable tracks are simply absent from the response. `HandleResolve` times the whole request (auth + decode + `Resolve` + response assembly) and logs `"audio_urls.handled"` with `duration_ms` alongside `requested`/`resolved` counts — the outer bound to compare against `AudioURLService.Resolve`'s inner `db_lookup_ms`/`presign_ms` split.
- **`StreamHandler`** (`adapters/handler/stream_handler.go`) — `HandleStreamAudio` (the proxy endpoint) sets `Content-Type` via `ports.AudioContentType(*out.Track.AudioRef)` and serves via `http.ServeContent` (range-request support). It logs twice for latency diagnosis: `"stream.serving"` right before `ServeContent` starts writing, with `setup_ms` (auth + `StreamTrackService.Execute`, i.e. everything before a byte reaches the client) and `size_bytes`; and `"stream.served"` after `ServeContent` returns, with `total_ms` covering the full byte transfer. Because `total_ms` is dominated by client read speed and the range-request pattern rather than server-side work, it answers "is this request stalling" rather than "is the server slow" — that distinction is `setup_ms` (and, one level deeper, `StreamTrackService`'s own `db_lookup_ms`/`storage_open_ms` split). `HandleRecover`, mounted at `POST /tracks/{trackId}/audio/recover`, calls `StreamTrackService.RecoverIfMissing` and returns 202 — this is the client's playback-error hook described above.

`AudioContentType` is the single source of MIME truth for both the upload side (object storage sets it on `PutObject`) and the serve side (the proxy stream endpoint labels the response). The two must agree: iOS and expo-audio decode progressive audio by `Content-Type`, so an m4a served as `audio/mpeg` fails to play. Legacy mp3 refs default to `audio/mpeg`.

`AudioURLSigner` is an optional capability detected by type assertion and never required. Object storage satisfies it via presigned GET; the filesystem store does not, and callers fall back to the proxy stream endpoint. Presigning is a local HMAC over the request with no network call to storage, so it is cheap enough to mint per track at queue-build time, though `maxAudioURLBatch` still caps one request so a queue cannot sign thousands of objects. Tracks that cannot be signed — unknown, not owned, not ready, or no signer configured — are simply absent from the resolve response, and the client streams those through the proxy. `HandleRecover` is the client's error hook for presigned streams, which bypass the proxy's missing-file recovery; it is idempotent and a no-op when the file is really there.

Path-traversal tests only assert backslash rejection on Windows: on Linux `..\windows\system32` is a single valid filename and correctly not traversal.
