Playback (server) is deliberately thin: per ADR-0010, the live `Queue` (advance/prev/shuffle/repeat) is owned entirely by the mobile client (`apps/mobile/src/shared/playback/queueStore.ts`, see [shared-playback](../mobile/shared-playback.md)). This backend context persists only a snapshot of it — the server half of the Memento pattern used for resume-on-reopen.

**Domain** (`domain/queue_state.go`): `QueueState{UserId, TrackIds []string, CurrentIdx, PositionMs, Shuffled, RepeatMode, SourceId, NaturalOrder []string, UpdatedAt}`. `TrackIds` is deliberately `[]string`, not `[]catalog/domain.TrackId` — playback references catalog tracks by id across the context seam rather than coupling to catalog's identity type for a snapshot the server never reasons about domain-wise. `TrackIds` is the queue in *play* order; `NaturalOrder` is the same ids in their pre-shuffle (album/playlist/library) order, letting the client rebuild the exact shuffled sequence AND un-shuffle back to the original order after relaunch — opaque to the server, carried through and never reasoned over, empty for older rows/clients (migration `009_playback_queue_natural_order.sql`).

`RepeatMode` is a three-state enum (`RepeatOff` zero-value / `RepeatAll` / `RepeatOne`) with `String()`/`ParseRepeatMode`, mirroring the mobile `RepeatMode` union.

All construction funnels through the unexported `newQueueState`, the single invariant gate: `PositionMs >= 0`, then two named helpers carry the rest — `emptyIfNil` normalizes nil `TrackIds`/`NaturalOrder` to `[]string{}` so callers and JSON serialization never see nil, and `indexWithinQueue` returns 0 for an empty queue and rejects an out-of-range `CurrentIdx` otherwise. Fields are passed in via `QueueStateInput` (`UserId`, `TrackIds`, `CurrentIdx`, `PositionMs`, `Shuffled`, `RepeatMode`, `SourceId`, `NaturalOrder`) rather than a long positional argument list — `TrackIds` and `NaturalOrder` are both `[]string`, so a positional swap would compile silently; grouping them in one struct removes that transposition hazard and localizes future field additions. Gate violations return `*domain.ValidationError`, which structurally implements `httputil.StatusError` (status 400 as a plain int — no `net/http` in the domain); `ParseRepeatMode` rejects unknown modes the same way. Three public constructors funnel through the gate — `NewQueueState(in)` (fresh, stamps `UpdatedAt=now`), `RehydrateQueueState(in, updatedAt)` (reconstitutes from storage, preserving stored `UpdatedAt` — so a corrupt row can't produce an invalid `QueueState`), and `EmptyQueueState(userId)` (the canonical "no queue" value, used whenever no row exists for a user; it routes through the gate like the others and panics on error, since empty input cannot fail validation).

**Ports**: `ports/queue_state_repo.go` defines `QueueStateRepository{Upsert, GetForUser}` — a 2-method port, one per operation, no read/write coupling. `ports/now_playing.go` defines `NowPlayingReader{Lookup(ctx, userId, trackId)}` returning `(*NowPlayingTrack, error)` — the result is nil with a nil error when the track is absent (deleted, unknown, or malformed id), which resume treats as "no snapshot", not a failure. `NowPlayingTrack` is a minimal display-ready snapshot (Id/Title/Artist/ArtworkURL/DurationSeconds/AcquisitionStatus), mirroring catalog track data by value across the context seam.

**Service** (`service/queue_service.go`): `QueueService.Save` parses the wire `RepeatMode` string, constructs a `QueueState` (rejecting invalid input before any I/O), and upserts. `QueueService.Resume` returns the saved snapshot or `EmptyQueueState` — callers never receive nil, so the handler needs no nil-check. `ResumeView` wraps Resume plus the currently-playing track's display snapshot (`ResumeView{State, CurrentTrack}`), so the client can render now-playing from this one small call instead of blocking on a full library rehydrate; `CurrentTrack` is nil when the queue is empty, the index is out of range (both decided by the `currentTrackId` helper, which reports whether anything is playing), or the track can't be found. `NewQueueService(repo, nowPlaying)` takes both dependencies as required parameters — a miswired composition root fails at construction instead of silently omitting `CurrentTrack` (tests pass an in-memory fake).

**Adapters**: `adapters/handler/queue_handler.go` exposes `PUT /queue-state` (save — request now includes `natural_order`) and `GET /queue-state` (resume, via `ResumeView`) behind `auth.RequireUserID`, mapping wire DTOs (snake_case JSON) to/from the service input/output; the response carries `natural_order` and an embedded `current_track` (`omitempty` — id/title/artist/artwork_url/duration_seconds/acquisition_status). Errors go through `httputil.HandleServiceError`: domain `ValidationError`s render as 400 with their message; anything else is logged and returned as a generic 500. `adapters/catalogbridge/now_playing_reader.go` implements `NowPlayingReader` against a narrow local `trackReader` interface (`GetByID` only) rather than catalog's full `TrackRepository` port — the bridge takes only the read it actually calls, out of that port's full surface — translating a catalog Track into playback's display snapshot; a malformed track id and a missing row both return through the `trackAbsent` helper — absent, not an error — so resume degrades to "no snapshot" instead of failing the whole call. `adapters/persistence/queue_state_repo.go` (`PgxQueueStateRepository`) is a single-row-per-user upsert (`ON CONFLICT (user_id) DO UPDATE`) against `playback_queue_state` (see [playback-queue-state-table](../data/playback-queue-state-table.md)), storing `track_ids`/`natural_order` as native array columns and `repeat_mode` as its string form, rehydrating via `domain.RehydrateQueueState(QueueStateInput{...}, updatedAt)` so the same invariant gate applies on read.

## Structured queue source (2026-07-25)

`source_id` is stored as a packed string (`library` / `playlist:<id>:<url-encoded name>` / `search[:<url-encoded query>]`), and the mobile client used to do that packing and parsing itself — string surgery over a format the server owns, with a URL-encoding step whose only purpose was to stop a `:` in a playlist name from reading as a separator.

`domain/queue_source.go` now owns the format: `QueueSource{Kind, PlaylistId, Name, Query}` with `Format()` and `ParseQueueSource()`. The wire carries a structured `source` object; storage is unchanged, so existing rows parse as-is.

The response emits **both** `source` and the legacy `source_id`, and `PUT` accepts either (`source` wins when present). That is deliberate: a shipped client reads `source_id`, and the field cannot be dropped until every client reads the structured one.
