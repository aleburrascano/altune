This is an **aggregate-owning, DB-and-storage-backed** context. The Logic family carries the domain core (the pure `Track`/`Playlist`/`FeaturedArtist` methods and the dedup/library-lens value objects), and the Persistence and Functional families carry most of the weight because this is the app's durable store and its public library/playlist HTTP surface. It owns no rendered component and no client-side query cache, so the display family (Derivation, Liveness) and the cache family (Invalidation) reject cleanly; the environment family reduces to the two trust boundaries it actually has — the on-disk audio path and untrusted HTTP/query input.

## SELECTED

- **Table** — the pure, I/O-free core: `computeDedupKey` with its case-fold / whitespace-collapse / special-strip rows and the all-empty `||` boundary (`dedup_test.go`); `ParseTrackId` / `ParsePlaylistId` / `ParseAcquisitionStatus` / `AcquisitionStatus.String` / `TrackId.IsZero` (`track_test.go`, `playlist_test.go`); `ParseLibrarySort` (incl. the `popularity` reject), `LibrarySort.String`, `FailureMessage` (nil / known / unknown reason) and `TotalDurationSeconds` skipping nil durations (`library_lens_test.go`); `FeaturedArtist.IdentityKey` (mbid → deezer → name precedence) and `NewFeaturedArtist` trim/reject (`featured_artist_test.go`); `Track.IsStreamable` over the status × audioRef truth table and the empty/blank-album → title fallback at its exact boundary (`track_test.go`); the 100-char playlist-name cliff (`playlist_test.go`); and `trackAddedPayload`'s album-nil-vs-title mapping (`add_track_payload_test.go`).
- **Reducer** — the `Playlist` aggregate is a `(state, event) → state` machine and every legal transition plus its illegal pairs is a case: `AddTrack` appends at the next position and rejects a duplicate; `RemoveTrack` renumbers the survivors contiguous and returns false for an absent track; `Reorder` rejects a length mismatch and an unknown track (`playlist_test.go`). The `Track` lifecycle is the reducer the acquisition record names as living here: `MarkReady` / `MarkFailed` / `RevertToPending`, each asserting the resulting status, the cleared/set `AudioRef` and `FailureReason`, and the illegal empty-`audioRef` / empty-`reason` rejections (`track_test.go`). The service layer drives the same transitions through the ports (`TestPlaylistMembershipService_*`, `service_test.go`).
- **Cross-surface contract** — the module publishes one shape the mobile client consumes, `service.TrackDTO`, and the `CLAUDE.md` invariant is that the wire response and the `track_added_to_library` SSE payload never diverge — both are that DTO. This side pins the literals: `trackAddedPayload` carries `id`, the legacy `track_id`, `title`/`artist`, the album-or-null, and `acquisition_status` (`add_track_payload_test.go`); `TestHandleCreateTrack_ResponseShape` pins the required response fields; and the playlist mutation payloads pin their keys and value types — `playlist_renamed` (`name`), `track_removed_from_playlist` (`playlist_id`/`track_id`), `playlist_reordered` (`track_ids` as `[]string` in order) (`playlist_events_test.go`). The **derived** guardian — the test that reads these names/fields out of the Go source at test time rather than restating them — lives on the consumer, as with acquisition: `shared/api-client`'s `TrackResponse` contract test and `shared/events`' `eventContract` scan. The known drift (`featured_artists[].mbid`/`deezer_id` omitted vs. the client's `| null`) is recorded in `programme.md` Outstanding and owned by the mobile `shared/api-client` slice.
- **Legacy / compat** — data written by an older version still loads. A track acquired before the `audio_version` column existed resolves with an empty version so the client keeps its existing copy rather than re-downloading (`audio_url_test.go`); a single saved with no album resolves its album to the title, applied in the aggregate at both `NewTrack` and `SetAlbum` (`track_test.go`, and `trackAddedPayload` empty-album cases); and the payload keeps the legacy `track_id` alongside the new `id` for older clients (`add_track_payload_test.go`).
- **Persistence round-trip** — this is the slice that owns the durable round-trip the acquisition record defers here, exercised against a real Postgres behind `DATABASE_URL` (skipped otherwise). `Track` Add → GetByID returns every column including `DedupKey` and pending status; `Update` persists a `MarkReady` status + `audio_ref`; `Delete` returns true then false on replay; a second Add of the same title/artist/album hits the dedup conflict and returns `created=false`; `FeaturedArtists` round-trip through the join table by MBID and by Deezer id (`track_repo_test.go`, `featured_artist_repo_test.go`). `Playlist` Create → GetByID, `AddTrack`/`RemoveTrack` membership, and `ReorderTracks` positions all read back as written (`playlist_repo_test.go`). Deleting the write breaks the read-back assertion in each. The filesystem store round-trips store → stream → exists → delete (`filesystem_test.go`); the object-storage adapter does the same behind `OCI_S3_*` (`object_storage_integration_test.go`).
- **Idempotence / replay** — applying twice equals applying once, at every replayable input: dedup makes a repeated add return the existing track, never a second row (`service_test.go` "duplicate returns existing", `track_repo_test.go` dedup conflict); a batch add skips a duplicate inside one request and a track already a member instead of failing the batch, and a batch remove skips a non-member (`service_test.go`, `playlist_handler_test.go`); `SetTrackNumber` is fill-only and a second call refuses to overwrite (`set_track_number_test.go`); the featured backfill is idempotent on re-run (`backfill_featured_test.go`); and `Delete` is idempotent at both the repo and service layers (second call returns false / `ErrNotFound`).
- **Adversarial** — the two trust boundaries the module actually has. The on-disk audio ref: every filesystem op rejects path traversal (`../etc/passwd`, `tracks/../../secret`, and the Windows `..\` form) with `path traversal rejected` (`filesystem_test.go`). Untrusted query input: the `ILIKE` library filter treats `%` and `50%` as literals, never wildcards (`library_lens_repo_test.go`). Untrusted HTTP input across the handlers: invalid UUID → 400, malformed JSON → 400, unknown id → 404, over-cap batch → 400 (`track_handler_test.go`, `playlist_handler_test.go`, `stream_handler_test.go`). Cross-tenant input: a track owned by another user is invisible — `GetTrackStatus` returns `ErrTrackNotFound` and `ListFeaturing` excludes it (`service_test.go`). The aggregate-only-mutation rules (`AudioRef`/`AudioVersion`/`AcquisitionStatus` never set by direct field write) keep a hostile caller from constructing an invalid `Track`.
- **Failure injection** — every I/O call site has a failing-path test. Repo errors propagate through every use case (`ErrOnAdd`/`ErrOnList`/`ErrOnDelete`/`ErrOnGetBy`/`ErrOnGetWithTracks`/`ErrOnCreate`/`ErrOnAddTracks`/`ErrOnRemoveTracks`, `service_test.go`). The audio store: a stream error over a *present* file stays ready and schedules a re-acquisition, a missing file marks the track failed and schedules, and an `Exists`-check error does *not* mark failed (`stream_track_test.go`, `stream_recover_test.go`). Presign failure skips only that track (`audio_url_test.go`); a per-track resolver error in the backfill is skipped, not fatal (`backfill_featured_test.go`); a batch that resolves to nothing never touches the repository (`service_test.go`); a missing filesystem object streams `os.IsNotExist` (`filesystem_test.go`).
- **Functional / acceptance** — the public HTTP surface asserted through `httptest` in ubiquitous-language terms: create/list/delete tracks, create/list/get/rename/delete playlists, add/remove/reorder membership, and the batch add/remove reporting `added`/`skipped`/`removed` counts (`track_handler_test.go`, `playlist_handler_test.go`). The product promises, not the implementation: adding a duplicate returns the existing track as 200 rather than erroring (dedup hit); a duplicate single-add is a 409 while a batch skips it as non-fatal; streaming serves the right MIME per container — `audio/mpeg`, `audio/mp4`, `audio/opus` (`stream_handler_test.go`); a missing audio file returns 404 and reconciles by scheduling a re-acquisition (`TestHandleStreamAudio_MissingAudio_SchedulesReacquisition`); and `sort=year` on artists is rejected 400 rather than silently falling back (`library_lenses_test.go`).
- **Invariant / architecture** — mechanically-enforced `CLAUDE.md` rules. Import direction via `.golangci.yml` depguard in CI: catalog never imports acquisition (goes through the `AcquisitionScheduler` port) and reaches discovery only through `adapters/discoverybridge`; domain purity. The aggregate invariants pinned by unexported construction plus method tests: `SetAlbum` recomputes `DedupKey` so the two never drift (`TestSetAlbum_KeepsTheDedupKeyInStep`, `_BlankFallsBackToTheTitle`); `FeaturedArtist.IdentityKey` stays in step with the `featured_artists` generated column (`featured_artist_test.go` "matches generated col"); `SetTrackNumber` is fill-only. The `DATABASE_URL`-gated `library_lens_repo_test.go` is the standing pin the rule names for every `LibrarySort` order and `ILIKE` change.
- **Regression** — the bug-shaped guards that fail the moment a shipped defect returns: an m4a container must serve `audio/mp4`, not `audio/mpeg` (`stream_handler_test.go` — the same shipped-container family as acquisition's F9); `AudioVersion` must change on every re-acquisition even for a byte-identical ref, else a client keyed on it keeps serving stale audio (`track_test.go` 100-acquisition no-repeat, and the round-trip through `MarkFailed`; `audio_url_test.go` new-version-after-reacquire); `track_number` must survive the create round-trip, since "the client sends it on every album-context save" (`track_handler_test.go`); and a pre-`audio_version` track still resolves (the legacy path above).

## REJECTED

- **Derivation** — no rendered component in a Go backend; the display/gating logic the category targets does not exist here. The two gates that decide what a client may play or how a track is grouped (`IsStreamable`, `FailureMessage`, the library-lens groupings) are pure and already covered under Table and Functional.
- **Property** — no generated/property harness on the Go surface (`fast-check` is mobile-only; no `go test -fuzz` is wired here). The invariants that would justify one — a `Playlist` reorder always yields a contiguous `0..N-1` permutation with no duplicates, `computeDedupKey` and `IdentityKey` collision behaviour — are pinned instead by the example tables in `playlist_test.go`, `dedup_test.go` and `featured_artist_test.go`. Reopen with a `go test -fuzz` pass over `computeDedupKey` / `FeaturedArtist.IdentityKey`; see the DEFERRED note.
- **Invalidation** — no client-side query cache in the backend. Catalog emits mutation events (`playlist_renamed`, `track_removed_from_playlist`, `playlist_reordered`); the mobile `shared/events` `INVALIDATION_MAP` owns which cache entries those refresh.
- **Liveness** — no rendered component. The live signals are the mutation SSE events, whose payloads are covered under Cross-surface contract (`playlist_events_test.go`); rendering them in place is the mobile slice's Liveness.
- **Concurrency / ordering** — this slice has no in-process reentrancy guard and no two operations that interleave: the use cases are request-scoped and stateless behind the repos. Ordering *within* a playlist is deterministic aggregate logic (contiguous positions), covered under Reducer, and the "persist a batch in one transaction and renumber inside it" atomicity rule is asserted through its final read-back state under Persistence round-trip (`playlist_repo_test.go` `ReorderTracks`), not by driving a partial-failure interleaving. The `recordingPlaylistPublisher` mutex is test scaffolding, not a slice guard.
- **Timing / dwell** — no user-visible duration is held here. The presigned-URL TTL is an expiry *window* asserted as a boundary (`ExpiresAt` is in the future, `audio_url_test.go`), not a dwell a user watches elapse.
- **Security** — the slice handles no secret in its own logic. The object-storage credentials and the presign signature live in the injected `AudioURLSigner` adapter and its config, outside this module (as acquisition's AcoustID key does); the resolver degrades to nothing when no signer is present (`audio_url_test.go` "no signer returns nothing"). The one adjacent concern — that an internal failure reason never reaches the user raw — is covered by `FailureMessage` mapping every reason to fixed human copy under Table. The path-traversal boundary and cross-tenant isolation are trust boundaries and sit under Adversarial.
- **Accessibility** — no user-facing UI in the backend.

## DEFERRED

- **Device e2e** — the catalog spine crosses a real Postgres and real object storage. The `DATABASE_URL`-gated persistence tests and the `OCI_S3_*`-gated storage tests exercise the real dependencies in-process when those env vars are set, but no full device/whole-stack lane boots the app, signs in, saves a track and streams it on hardware in CI. Unblocked by a live-stack integration lane or a device flow; tracked at programme level, not reopened per-slice.

## MUTATION AUDIT

Not run for this record. No mutation harness is wired on the Go surface in this repo (no `go-mutesting`/Stryker equivalent; the taxonomy's mobile tooling does not apply). Until one is, the standing proxy for "do these tests constrain rather than merely execute" is two-fold and both are CI-gated:

- the `DATABASE_URL`-gated `library_lens_repo_test.go` — a behavioral gate on the sort and filter surface: any `LibrarySort` order or `ILIKE` change that regresses the pinned rows fails the DB lane;
- the backend per-file coverage floor in `test-backend.yml`.

`programme.md` Outstanding records the recommended unblock verbatim: a `test-assassin` run over `internal/catalog/service` to establish whether the backend half of the programme needs work at all. That scoped pass over the pure service and domain core (`computeDedupKey`, the `Playlist`/`Track` methods, `FailureMessage`, `TrackToDTO`) is where a survivor would most likely hide.
