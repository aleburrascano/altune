## SELECTED

- **Table** — three pure functions with two or more branches each. `extFromUrl` (query-string strip before parsing, the `dot > slash` boundary that distinguishes `/a.b/c` from `/a/b.c`, a dotless path, the `.mp3` default). `formatBytes` (the `< 1024` bytes arm, each rung of the KB/MB/GB ladder at its exact 1024 boundary, the `value < 10` switch between `toFixed(1)` and `Math.round`, and the `unit < units.length - 1` clamp that must hold a terabyte at `GB` rather than walking off the array). `pinnedUri` (`ready` with a uri, `ready` without one, each non-`ready` status, absent entry) — it is the function `features/playback/loadNativeTrack.signedUrl` calls first for every library track, so its `undefined` arm is the whole fallback chain's hinge.
- **Reducer** — `usePinnedStore` is a `(state, action) → state` store: five actions (`pin`, `pinMany`, `unpin`, `unpinAll`, `reconcile`) over `entries: Record<string, PinnedEntry>` (four statuses) plus a `queue` and an `isWorking` flag. Every state × action pair the domain permits gets a case, not a diagonal: each action against an empty index, against an index holding each of the four statuses, and against a track that is mid-download. Illegal pairs asserted as rejected — `pin` on a `ready` or `downloading` entry must be a no-op that does not re-enqueue, and `pinMany` with nothing fresh must not touch state at all.
- **Property** — one law the store must never break: **every id in `queue` has an entry in `entries`**. Generated with `fast-check` (`^4.9.0`, already a devDependency, used in `shared/events` and `shared/playback`) over sequences of arbitrary actions. Its violation is the concrete bug this slice can produce — a queued id with no entry drives `downloadOne` into an early return that silently drops the download while the UI still shows a pending state. Shrunk counterexamples become Table rows.
- **Legacy / compat** — `loadIndex` parses `Paths.document/offline/pinned.json`, a file written by an arbitrarily old build of this app and restored from device backups. Its `typeof parsed !== 'object' || parsed === null` guard exists for exactly that. Fixtures for every historical and degenerate shape still reachable in the wild: absent file, empty file, `null`, a JSON array, a bare string or number, an entry with no `uri`, an entry carrying a status this version does not know, and an entry whose key and `trackId` disagree.
- **Persistence round-trip** — the category the taxonomy cites this slice by name for. Every mutating action writes the index; the done-condition is that a real double round-trips it — write, then read back what was written, then confirm that **deleting the write breaks the test**. Applied to `pin`, `pinMany`, `unpin`, `unpinAll`, `reconcile` and `downloadOne`'s `mark`, and to the relaunch path: a fresh `loadIndex()` must return exactly what the previous session persisted.
- **Idempotence / replay** — `reconcile()` is the canonical replayable input; it runs once per launch via `OfflineReconcileBridge` and `reconcile(reconcile(s))` must equal `reconcile(s)` for every index shape. Also `unpin` twice, `unpinAll` twice, `pin` on an already-`ready` track, `pinMany` over a set already pinned, and `repinIfPinned` delivered twice for the same `track_acquisition_completed` event — the SSE stream can redeliver, and a second re-pin must not leave two entries or two queue slots.
- **Adversarial** — three trust boundaries cross into this slice. **Disk**: `pinned.json` is untyped after `JSON.parse` and cast straight to `Record<string, PinnedEntry>`; the malformed and tampered shapes are enumerated under Legacy/compat and must degrade to an empty index, never throw and never crash a launch. **The presigned URL**: `extFromUrl` parses a server-produced string to choose a filename — a URL with no path, no extension, a dot only inside the query signature, or a `.` at the very end each has a case. **Filenames on disk**: `findPinned` matches by `startsWith(\`${trackId}.\`)`, so a partial write, a foreign file dropped in the directory, a subdirectory, and an empty `trackId` each get a case.
- **Failure injection** — the reason this slice is in the programme. Every I/O call site gets a test where it fails, using `__fs.failNext(kind)`: `createDirectory` (index dir and audio dir), `read` (`textSync` on a corrupt or locked index), `write` (disk full during `saveIndex`), `delete` (an OS-locked file under `deletePinned` / `deleteAllPinned`), `download` (`File.downloadFileAsync` rejecting mid-transfer), and `list` throwing inside `pinnedFilesOnDisk`. Plus the network side: `fetchAudioUrls` rejecting, and `fetchAudioUrls` resolving `[]` — the server omits rather than nulls an id it cannot sign, so an empty array is a normal response and must land the entry in `failed`, not hang the worker.
- **Concurrency / ordering** — `runQueue`'s `isWorking` flag is the same shape as the `flushOutbox` guard the taxonomy cites, and it must be shown removable-detectably: a test that fails without it. The orderings that are load-bearing: `pin` during an in-flight download must join the running queue rather than start a second worker; `unpin` mid-download must leave `downloadOne`'s post-await existence re-check to delete the landed file; `unpinAll` mid-download (the sign-out path) must do the same for every entry; and `repinIfPinned` firing while that same track is `downloading` interleaves an `unpin` and a `pin` around an awaiting `downloadPinned`. `isWorking` must be restored by the `finally` even when a download throws, or the queue is wedged for the rest of the process.
- **Security** — the presigned URL is a capability-bearing credential with a one-hour TTL, and this slice is the only place one is handled next to a plaintext file in the document directory. One narrow done-condition: **no signed URL ever reaches disk.** `pinned.json` must contain only `file://` local paths, never the download URL, never a query string; and `downloadPinned`'s return value — which is what `mark` persists as `uri` — must be the local file's uri, not the source URL.
- **Functional / acceptance** — the slice carries product promises that are assertable through its public interface (`usePinnedStore`'s actions, `pinnedUri`, `repinIfPinned`, `pinnedBytes`, `formatBytes`) in `docs/ubiquitous-language.md` terms with no reference to internals: a pinned Track resolves to a local file rather than a network URL; a Track whose file is gone is **not** offered as available offline; a kill mid-download retries on relaunch rather than being forgotten; unpinning during a download does not resurrect the Track when the download lands; and signing in as a different user leaves no pinned Track behind. There is no `docs/specs/` document for offline downloads — the promises are stated in `okf/mobile/shared-offline.md`, and the authors do not see it, which is the point of the blind protocol.
- **Invariant / architecture** — one rule here is mechanically checkable and load-bearing: **pinned audio lives under `Paths.document`, never `Paths.cache`.** It is the single design choice that separates this slice from `features/playback/audioPrefetch.ts`; putting a pinned file in the cache root lets iOS reclaim it silently, which is precisely the failure the feature exists to prevent, and nothing today would catch the edit. A scanner over the slice's own files asserting no `Paths.cache` reference, plus an assertion that every uri the store persists sits under the document root.
- **Regression** — the two dated incidents harvested below, plus every survivor this run produces.
- **Mutation audit** — see below.

## REJECTED

- **Derivation** — the category exists to force a derivation *out* of a component so its truth table becomes reachable. The slice's only component, `OfflineReconcileBridge.tsx`, computes nothing and returns `null`; it is eleven lines of mount effect. The derivations that read this slice's state — `LibraryRow`'s `offlineLabel`, `trackMenu`'s `offlineItem` four-arm status switch, `SettingsScreen`'s `downloadCount` — are all in feature slices and get the category there.
- **Cross-surface contract** — this slice consumes no Go-produced shape. It reaches the API only through `fetchAudioUrls`, and the `audioURLDTO` json tags (`track_id`, `url`, `expires_at`) are mapped to `ResolvedAudioUrl` inside `shared/api-client/audio.ts` — that mapping is slice 5's contract to derive, and recording it here so it is not lost between the two. The only Go-derived value that reaches this slice is the presigned URL string itself, and it is deliberately treated as **untrusted input rather than a contract**: `extFromUrl` makes no structural promise about it and falls back to `.mp3`, so its cases belong under Table and Adversarial. The one server behaviour this slice does depend on — `Resolve` *omitting* rather than nulling an id it cannot sign, so a single-id request can legitimately return `[]` — is asserted as a Failure injection case instead, because deriving "the loop `continue`s" from Go source text is a fragile scan where the equivalent client-side assertion is exact.
- **Invalidation** — this slice touches no TanStack Query key and holds no cached server state. It is *called by* `applyServerEvent` (`repinIfPinned` on `track_acquisition_completed`) alongside that handler's cache patches, but the invalidation policy is `shared/events`' `INVALIDATION_MAP` and is already gated in slice 1.
- **Liveness** — no component in this slice renders anything. `OfflineReconcileBridge` returns `null` and subscribes to one stable action (`usePinnedStore((s) => s.reconcile)`) precisely so it never re-renders. The screens that render pinned state — `LibraryRow`, `SettingsScreen`, `PlaylistDetailScreen` — live in `features/library` and `features/settings` and get their liveness tests in those slices.
- **Timing / dwell** — no duration is held, measured or displayed here; there is not a timer in the slice. The one timeout in the download path is `fetchAudioUrls`' 2500 ms abort, which lives in `shared/api-client` and is that slice's boundary.
- **Accessibility** — no interactive component, no announcement, no hit target. The a11y label that reports download state to a screen reader is built in `LibraryRow`.

## REGRESSION CANDIDATES

Harvested from `okf/mobile/shared-offline.md`, each a dated incident someone paid to learn. Recorded here so they survive the session; the blind authors do not see this list.

- **Identity boundary (2026-07-24).** Pinned downloads are not user-scoped — one index, one audio directory, loaded once at module init — so the boundary is enforced at the moment identity changes: `useSession` calls `unpinAll()` when the signed-in `user.id` *changes*, never on the first observation. Before it, signing out left the previous account's audio in the document directory indefinitely. The harm was precise: the next user could not *play* those tracks (both `pinnedUri` and `findPinned` are keyed by track UUID, and another account's library never names one), but the surviving index fed Settings a byte size **and a track count** belonging to the previous user. The sequential worker had the matching hole: a file downloaded across a sign-out became an orphan no startup pass could see, because `mark` drops the index write when the entry has vanished and `reconcile()` only walks entries that exist. `downloadOne` now re-reads the entry once the download settles and deletes the file when it is gone, on **both** the success and the failure path — a rejection after `File.downloadFileAsync` has written bytes strands a partial file just as readily.
- **Re-pin after the audio underneath changes (2026-07-26).** A pinned file is keyed by track id and a re-acquire replaces the audio at the *same* object key, so the ref stays valid while the bytes behind it change — and `signedUrl` prefers `pinnedUri` over the freshly presigned URL unconditionally. A downloaded track therefore kept playing the old recording forever after a successful re-acquire, indistinguishable from "re-acquire does nothing". `repinIfPinned` closes it, and its guard is the load-bearing half: completing an acquisition must never *start* pinning a track the user never downloaded. It is deliberately delete-then-download rather than an in-place overwrite, so a failed re-download leaves a `queued`/`failed` entry `reconcile` already understands rather than a stale file wearing a fresh label.
- **Files win over the index.** `reconcile()`'s third rule — an entry previously `ready` whose file is gone is **dropped**, not kept — is the one that matters most. An index claiming a track is downloaded when the file is gone (restore-from-backup, a manual clean) produces a track that shows as available offline and then fails to play with no network: the worst outcome this feature can produce, and worse than showing nothing.

## FINDINGS (pre-authoring, verified against the source)

- **The slice has no nested `CLAUDE.md`.** The repo rule states one is the file map of its directory; `shared/acquisition`, `api-client`, `events`, `playback`, `telemetry` and `ui` each have one, and `offline`, `auth` and `lib` do not. Adding a `__tests__/` directory here requires creating it, which this run does.
- **Two `??` fallbacks in `pinnedFiles.ts` are unreachable at runtime and mandated by the compiler.** `baseName`'s `uri.split('/').pop() ?? ''` and `extFromUrl`'s `url.split('?')[0] ?? ''` — `String.split` always returns at least one element, so neither right-hand side can execute, but `noUncheckedIndexedAccess: true` makes both required to typecheck. They cap this file's branch coverage below 100% and no test can close them. Carried to LEFT DARK rather than removed.
- **`reconcile()` drops a `failed` entry.** Its requeue arm is `status === 'queued' || status === 'downloading'`, so an entry that failed and has no file is dropped on the next launch rather than kept. Verified against the consumer before calling it a defect: `trackMenu.offlineItem` renders `failed` as "Retry download" and every other absent state as "Download", and **both call `pin`** — so the user-visible difference is one word of label after a relaunch, and the action is identical. Not a defect; recorded because it is the kind of asymmetry a reader assumes is one.

## FINDINGS RESOLVED (authoring pass)

Nine findings came back from the four blind authors and the cartographer. Each was verified against the source before acting; five were confirmed defects and fixed, four were not.

- **A transient listing failure dropped the entire pinned library, durably** (unit-4) — confirmed and **fixed**. `pinnedFilesOnDisk` swallows a listing error and returns `[]`, so `findPinned` answered "no file" identically whether the directory was empty or unreadable, and `reconcile` then dropped every `ready` entry and persisted the emptied index. `reconcile` now returns early on `pinnedDirReadable() === false`. The highest-severity finding of the run; detail in [shared-offline](../mobile/shared-offline.md).
- **A re-pin during an in-flight download published the superseded bytes as `ready`** (unit-3) — confirmed and **fixed**. `repinIfPinned` runs `unpin` then `pin` synchronously, so the entry is gone and back before the in-flight download settles, and a cancellation check asking "does the entry still exist" found it present. The check now asks whether the entry is still `downloading`, which is the question that was always meant: unpin, `unpinAll`, re-pin and a reconcile requeue are all supersessions, and existence detected exactly one of the four.
- **`pin` and `pinMany` re-admitted an already-`queued` id** (unit-2) — confirmed and **fixed** via a shared `needsDownload` predicate: only an absent or `failed` entry is enqueued. A second "Download all" over a batch still working through its queue duplicated every id that had not yet reached the front, and the worker downloaded each twice.
- **`loadIndex` accepted a JSON array** (unit-2) — confirmed and **fixed**. `typeof [] === 'object'`, so an array walked through a guard whose evident purpose is to reject anything that is not a record.
- **`extFromUrl` returned a bare `"."` for a path ending in a dot** (unit-1) — confirmed and **fixed**; the author's `it.failing` was promoted. Defensive rather than live: the backend's ref builder always names an extension, so no presigned URL reaches it today.
- **`saveIndex` swallows every write failure silently** (unit-2, unit-3) — verified, **not a defect**. It is the documented best-effort contract, and the next launch's `reconcile` heals the divergence from disk. Recorded because it is silent, with no retry and no telemetry, so the divergence persists until the next successful write.
- **`reconcile` drops a `failed` entry** (pre-authoring) — verified against the consumer, **not a defect**. `trackMenu.offlineItem` renders `failed` and absent identically as a `pin` call, so the difference after a relaunch is one word of label with identical behaviour behind it.
- **`findPinned('')` matches any dotfile** (unit-1) — **not a defect**; no production path passes an empty id. Recorded as observed behaviour.
- **A partial file is adopted as `ready`** (unit-4) — **real, deliberately not fixed.** `findPinned` matches `<trackId>.*` with no completeness check, so a truncated file left by a killed download is indistinguishable from a whole one. The fix trades a truncated file against needlessly re-downloading a complete one and needs a completion marker the design does not have; carried as a known limit rather than settled inside a QA run.

## Re-derivation — audio version gate (2026-07-31)

`pinnedUri` gained an `expectedVersion` parameter and a self-healing re-pin, `downloadOne` records the version it fetched under, `reconcile()` carries that version forward, and `PinnedEntry` gained `version?: string`. Re-deriving which categories the changed surface triggers:

- **Table** (already selected, extended) — `pinnedUri` is no longer a one-dimensional status check. Its truth table is now status × (expected version vs recorded version), with three distinct "serve the local copy" reasons that must not collapse into each other: versions match, expected is `undefined` (URL resolution failed — an offline load must still play), and expected is `''` (the server has no version — a track not acquired since the column landed must not re-download on every play). Each is a row in `pinnedStore.version.test.ts`, and the status gate is re-asserted on top of a *matching* version so a version match cannot resurrect a `failed` entry.
- **Regression** (mandatory — bug fix) — the incident below.
- **Idempotence / replay** (already selected, extended) — repeated `pinnedUri` calls during the heal must not stack re-pins. Covered: three consecutive mismatching calls issue exactly one `fetchAudioUrls`, because the first re-pin leaves the entry `downloading` and the status gate then declines before reaching the version gate.
- **Persistence round-trip** (already selected, extended) — the recorded version must survive the index write and the relaunch read, and must survive `reconcile()`. The `reconcile` case is the load-bearing one: rebuilding the entry from scratch instead of spreading it would drop the version on every launch, mismatch every pinned track, and silently re-download the entire offline library. The existing worker suite covers the write side (its `toEqual` assertions now name `version`).
- **Cross-surface contract** (still rejected here) — `version` crosses the same `audioURLDTO` → `ResolvedAudioUrl` boundary the original rejection assigned to `shared/api-client`, and it is derived there. The rejection stands for the same reason; recorded so the new field is not assumed to be uncovered.
- **Concurrency / ordering** (already selected) — the heal can fire while that track is mid-download. No new ordering: `repinIfPinned`'s existing unpin-then-pin and `downloadOne`'s still-`downloading` supersession check already own that interleaving, and the version gate reaches them only through the `ready` arm.

### Regression — a re-acquisition the device never heard about (2026-07-31)

The 2026-07-26 entry above fixed this bug's foreground half and is the reason the tail was so hard to see. Both `repinIfPinned` and the prefetch `evictCached` hang off one live SSE event, `track_acquisition_completed`. Nothing else ever re-examined a cached file: `pinnedUri` answered from the index, `findPinned` matched `<trackId>.*`, and `reconcile()` checked only that a file *exists* — none of them had any notion of *which* audio the file held. A re-acquisition completing while the app was backgrounded, offline, or not running therefore left the old recording authoritative on that device permanently.

The reporting path is worth keeping, because every signal pointed away from the client: the admin panel showed the job succeeded, the resolved source URL was the correct new video, the pipeline logs showed the duration heuristic correctly skipping the bad candidate, and the bytes in S3 were right. Deleting the track and re-adding it "fixed" it — which reads as the bucket healing, but is actually a **new `trackId`** missing both caches by key. The natural hypotheses (a failed S3 overwrite, a wrong duration sent on re-acquire) were both wrong, and both are disproven by the same fact: `BuildAudioRef` is deterministic, so re-acquisition overwrites the same object and every id the client could key on stayed identical.

The fix makes the event an optimisation rather than the only thing standing between a re-acquisition and a permanently wrong file. What must stay true, and what a future edit could quietly break:

- The three "no expectation" arms must keep serving the local copy. Turning `''` or `undefined` into a mismatch trades this bug for a worse one — an offline device that refuses to play its own downloads.
- `reconcile()` must keep carrying `version`.
- A mismatch must re-pin as it declines, not merely decline; declining alone fixes playback for that session while leaving the wrong bytes on disk for the next offline launch.
