Those are the **per-file minima and the aggregate at once**, which is the first time in this programme the two have coincided: every one of the thirteen files sits at 100 on all four metrics, verified per-file before the floor was committed, because Jest applies a glob threshold to each matching file individually — the trap that has left slice 1's floor red since it landed. Running the exact CI command (`npx jest --coverage --ci`) confirms the only threshold breaches in the repo remain `shared/events`' `sse-client.ts` and `trackCachePatch.ts`; this slice adds none.

There is **no LEFT DARK section**, and that is worth stating precisely rather than celebrating. The cartographer classified two guards in `errors.ts` as impossible-at-their-production-call-sites — the non-object arms of `isAbort` and `isSessionFetchFailure`, which receive Supabase's `AuthError | null` and a `fetch` rejection respectively, neither of which can be a primitive. They are covered anyway, because both functions are exported with an `unknown` parameter and the tests drive them through that public signature. So the line is executed; the claim is not that a production path reaches it.

This is the slice every other slice's network path runs through. `index.ts` is the app's **only** `fetch` call site outside the SSE client, and it is where four distinct failure modes are told apart from one another — a dead session, an unreachable auth server, an expired deadline and a caller cancellation. The 2026-07-25 weak-signal incident is the record of what happens when two of them are conflated: a transport failure reported as `ApiError(401)`, which the retry predicate correctly refuses to retry, so a radio dropout became a permanently empty library until the app was restarted. Every discrimination in `errors.ts`, `deadline.ts` and `send()` exists because of that, and none of it is currently constrained by a test.

## SELECTED

- **Table** — the slice is mostly pure functions with two or more branches, and each gets its boundaries as rows, not a diagonal. `isRetryable` at its exact hinges — `429` yes, `428` no, `499` no, **`500` yes** (`>=`, not `>`), `NetworkError` of either `failure` yes, a bare `Error` no, a non-error no. `isAbort` / `isSessionFetchFailure` over `null`, `undefined`, a primitive, an object with no `name`, the wrong `name`, the right `name`. `libraryQueryString` — the empty query returning `''` and **not** a bare `'?'`, `q` only, `sort` only, both, and an empty-string `q` which the truthiness guard drops. `_contentUrl`'s `limit === undefined` arm versus `limit === 0`, which is defined and must appear in the URL. The query builders in `searchDiscovery` (`kinds` non-empty vs empty array vs absent; `limit !== undefined` including `0`; `offset !== undefined && offset > 0`, so `0` is deliberately omitted; `saveHistory === false` only, so `true` and `undefined` both omit the param), `listTracksFeaturing` (`mbid`, `deezer_id != null` **including `0`**, truthy `name`, and all-absent), `getEnrichment` / `kindTitleQs` / `getArtistContent` / `getAlbumTracks` (four optional params) / `getLyrics` (`subtitle != null && length > 0`). `normalizeResult`'s two `??` arms. `readBody`'s three short-circuit statuses — `202`, `204`, `304` — each as its own row, plus `200` and a `201` that must parse.
- **Property** — `isRetryable` states a law over an input space too large to enumerate: for every integer status, an `ApiError` is retryable **iff** the status is `429` or at least `500`. Generated with `fast-check` (`^4.9.0`, already a devDependency, used in `shared/events`, `shared/playback` and `shared/offline`) over `fc.integer()`, which catches the off-by-one at `500` and the sign errors a hand-written table would have to guess at. A second law covers the query builders, which are the slice's most-repeated shape: for every parameter record, the URL a builder produces **parses back through `URLSearchParams` to exactly the parameters that were set** — no bare `?`, no key present for an omitted value, no value lost to encoding. That is the invariant the 2026-07-25 `/albums&name=X` defect broke, and it broke it only for the input nobody enumerated.
- **Cross-surface contract** — this slice **is** the cross-surface boundary; `types.ts`'s own header flags hand-maintenance as the sync risk. Two contracts, both **derived from `services/go-api` source at test time**, never restated as literals, on the model of `shared/events/__tests__/eventContract.test.ts`. **(a) Routes:** every path literal this slice sends must resolve to a route registered in the Go router — `internal/app/app.go`'s `/v1` tree plus each handler's `Routes()` — matched on method as well as path, so a client `PATCH` against a `PUT`-only route fails here rather than in production. **(b) Shapes:** the json tags of the Go DTO must equal the keys of the TS type that receives it, for `TrackDTO`↔`TrackResponse`, `ListTracksResponse`, `PlaylistResponse`, `PlaylistDetailResponse`, `AlbumGroupDTO`↔`AlbumGroup`, `ArtistGroupDTO`↔`ArtistGroup`, `audioURLDTO`↔`ResolvedAudioUrl` and the queue-state pair — with each Go `omitempty` field required to be optional or nullable on the TS side, since that is precisely the drift that produces an `undefined` where the client expects a value. `audioURLDTO`'s `expires_at` is the field `shared/offline`'s record handed forward to this slice: the Go DTO carries it, `ResolvedAudioUrl` drops it, and the contract test must record that as a deliberate narrowing rather than let it read as an oversight.
- **Legacy / compat** — the client is deployed ahead of and behind the server, and five coercions exist for exactly that. `searchDiscovery` normalises a server that omits `total` / `offset` / `has_more` into **a single full page rather than an empty one**, so an older API degrades instead of rendering nothing; it also tolerates absent `results` and absent `sections`. `normalizeResult` maps `undefined`→`null` for `subtitle` and `image_url`, which Go's `omitempty` drops. `getLyrics` coerces `synced_lines` and `writers` to `[]` for the same reason. `playback.ts` reads the structured `source` while the server still emits `source_id` for older clients, and `natural_order` is empty for rows written before it existed. `TrackResponse.failure_message` and `featured_artists` are optional because tracks predate them. Every one of those gets a fixture of the *old* wire shape, including absent and explicit-`null` variants.
- **Adversarial** — `readBody` casts `await response.json()` straight to `T` with no validation, so every response body is untrusted input that the slice's own transform functions then walk. The cases: a body that is `null`, an array where a record is expected, a record where an array is expected (`results`, `sections`, `urls`, `synced_lines` as a string), a `sections` entry with no `items`, a `202`/`204` short-circuit reaching a caller that immediately dereferences the result, a truncated body (invalid JSON) which must become `NetworkError('transport')` and not a `SyntaxError`, and a body that is valid JSON but the wrong document entirely. Also the *outbound* boundary: `provider` is interpolated into discovery and enrichment paths **unencoded** while `externalId` is `encodeURIComponent`'d — a provider or id containing `/`, `?`, `#` or `..` gets a case, since both values arrive from a server-supplied `DiscoverySource`.
- **Failure injection** — the category this slice exists for; it is the app's I/O layer and every call site can fail. `supabase.auth.getSession()` **resolving** `{session: null, error}` (it does not throw — that is the trap the fail-fast was written for) with a stale-refresh error, with an `AuthRetryableFetchError`, and with a session present but no `access_token`. `fetch` rejecting with a transport error, rejecting with an `AbortError` that is neither the deadline's nor the caller's, and hanging until the deadline fires. `response.json()` rejecting. Every status class: `400`, `401`, `403`, `404`, `409`, `429`, `500`, `503`. And the composite the incident was made of — a weak link where `getSession` fails transport-wise must produce a **retryable** `NetworkError`, never `ApiError(401)`.
- **Concurrency / ordering** — `startDeadline` composes two independent abort sources and `send` classifies the result, so the *order* of its three checks is load-bearing and each is removable-detectably. `deadline.cancelled()` is tested before `deadline.expired()`, and the caller's `AbortError` must be rethrown **as-is**: relabelling it `NetworkError` makes it retryable, and TanStack would resurrect queries the component already cancelled on unmount. An external signal that is **already aborted** at call time must be relayed synchronously — `addEventListener` on a settled signal never fires, so without that arm the request hangs on precisely the deadline meant to prevent hangs. `release()` runs in a `finally`, so it must clear the timer and detach the listener on the throwing path as well as the returning one, and a test must show a leaked timer when it does not. `fetchAudioUrls` nests a 2500 ms caller abort inside the 15 s deadline; the inner one must win. And `markSessionExpired()` must be called **before** the `!response.ok` throw, or a 401 throws without ever marking.
- **Timing / dwell** — `REQUEST_TIMEOUT_MS` is 15 s and `fetchAudioUrls`' abort is 2500 ms, and both are user-visible as the length of a spinner; the whole point of the 2026-07-25 deadline work was that an unbounded one spins forever. The done-condition is the taxonomy's: **asserted mid-window**, not by advancing all timers. At 14 999 ms the request is still in flight and nothing has been thrown; at 15 000 ms it is a `NetworkError('timeout')`. Same for 2499/2500 ms on `fetchAudioUrls`. A test that advances timers to infinity and asserts the end state cannot tell 15 s from 1 s, which is exactly how a shortened dwell survived elsewhere in this programme. Fake timers, and the microtask queue must be flushed until `fetch` is actually in flight before advancing — otherwise the deadline has not been armed and the advance is a no-op.
- **Security** — the access token is handled here and nowhere else on the request path, and the written rules are "never store secrets in `AsyncStorage`" and "never decode or manipulate the access token here". Done-conditions, all narrow and assertable: the token appears **only** in the `Authorization` request header — never in a URL, never in a query string, never in a thrown `ApiError` or `NetworkError` message, and never in the message `authorization()` builds from the Supabase error. `audioStreamUrl` returns a bare URL with no credential in it, because that string is handed to the native player and to logs; the credential rides `audioRequestHeaders` instead. `audioRequestHeaders` returns `{}` rather than the string `Bearer undefined` when there is no session. And this slice must not decode, split or inspect the token — a scanner over its own source asserting no JWT handling.
- **Functional / acceptance** — the product promises are assertable through the public interface (`apiFetch` and the typed functions) in `docs/ubiquitous-language.md` terms with no reference to internals: a request made without a session **never leaves the device**; a weak connection produces a retryable failure so the screen recovers on its own rather than staying empty until relaunch; a screen the user navigated away from stays cancelled and is not resurrected; a request that hangs gives up rather than spinning forever; a server that rejects the token offers re-auth rather than silently signing the user out; and submitting an in-app report returns the issue number the tester is shown. There is no `docs/specs/` document for the HTTP layer — the promises live in `okf/mobile/shared-api-client.md`, which the blind authors do not see, which is the point of the protocol.
- **Invariant / architecture** — four rules in this slice's `CLAUDE.md` are mechanically checkable and none is enforced today. **(a)** `apiFetch` is the single fetch wrapper: no file in the slice other than `index.ts`'s `send` calls `fetch(`, and no typed function bypasses `apiFetch`. **(b)** Every request gets a deadline: `send` is the only `fetch` call site and it always passes `deadline.signal`. **(c)** Retry policy lives only in `isRetryable`: no loop and no recursive re-send inside `apiFetch` — an inner retry would silently re-send non-idempotent POSTs whose first attempt may already have been applied, and would multiply against TanStack's own retries. **(d)** `api-client` imports nothing from `shared/telemetry` and nothing from any feature — the two-way dependency that the 2026-07-17 structure audit broke by moving `recordEvent` out.
- **Regression** — the dated incidents harvested below, plus every mutation survivor this run produces.
- **Mutation audit** — see below.

## REJECTED

- **Derivation** — the category exists to force a derivation out of a component so its truth table becomes reachable. This slice has no component: thirteen `.ts` files, zero `.tsx`, nothing rendered and nothing gated. The derivations that consume its output — the failed-acquisition copy in `LibraryRow`, the "See all &lt;kind&gt;" affordance driven by `ResultSection.has_more`, the report dialog's 400-vs-404 split — all live in feature slices and get the category there.
- **Reducer** — no store and no `(state, event) → state` function. The only stateful object in the slice is the `Deadline` closure (`expired` / `cancelled` / a timer), and it is three lines of flag rather than a transition table; its states are covered as Table rows and its interleavings under Concurrency / ordering, which is where the value actually is. Reaching for Reducer here would restate those cases in a worse shape.
- **Persistence round-trip** — nothing in this slice survives process death. It writes no file, touches no `AsyncStorage` and holds no cache; `apiBase` is a module-level constant read from the environment at import. The one thing on the request path that *is* persisted — the Supabase session in the keychain — is owned by `shared/auth` and is this slice's dependency, not its state.
- **Invalidation** — this slice sits **below** the query layer and knows nothing about it. It imports no TanStack Query key, holds no `QueryClient`, and never invalidates anything; callers decide what to refresh after a mutation resolves. The `INVALIDATION_MAP` that the taxonomy cites is `shared/events`' and is already gated in slice 1; `shared/lib/query-keys.ts` is slice 6.
- **Liveness** — no component in this slice renders anything, so there is no screen that can go stale. Every consumer that renders server-mutable state fetched through here gets its liveness test in its own feature slice, against the query cache rather than against `apiFetch`.
- **Idempotence / replay** — the category needs an input that can be *delivered* more than once into accumulated state. This slice accumulates nothing: each `apiFetch` call is independent, and the deliberate absence of an internal retry loop (Invariant (c)) means the layer never re-sends a request at all — which is the opposite property, and is asserted there. The replay-shaped guard on the path, `markSessionExpired`'s `if (expired) return`, belongs to `shared/auth`; this slice's obligation is only to call it, which Concurrency / ordering pins.
- **Accessibility** — no interactive component, no announcement, no hit target, no rendered output of any kind.

## REGRESSION CANDIDATES

Harvested from `okf/mobile/shared-api-client.md`, each a dated incident someone paid to learn. Recorded here so they survive the session; the blind authors do not see this list.

- **The fake 401 (2026-07-25).** `apiFetch` collapsed every `getSession()` failure into `ApiError(401)`. But `getSession` hits the network when the access token needs refreshing, and on a weak link that call fails with a transport error — so a radio dropout was handed the one error code the retry predicate is guaranteed never to retry. Every query on the screen failed at once and none came back until the app was restarted. The split now mirrors Supabase's own discriminator, `error.name === 'AuthRetryableFetchError'`, matched on the *name* rather than `instanceof` so `errors.ts` stays free of a Supabase import and a test can build the case from a plain object. The load-bearing half is that `getSession` **resolves** with `{session: null, error}` rather than throwing: the original `try/catch` caught nothing and let the doomed request go out unauthenticated, then reported the server's 401 as though the server had an opinion.
- **No timeout anywhere (2026-07-25).** React Native's `fetch` has no default timeout, so a request on a dying connection hangs forever: no error, no retry, no empty state, a spinner until relaunch. `startDeadline` gives every request 15 s. It **composes** the caller's signal with the internal timer rather than replacing it, because the two aborts mean opposite things — timer fired is a retryable `NetworkError('timeout')`, caller aborted is the original `AbortError` rethrown untouched. Relabelling a cancellation as a timeout would make it retryable and turn an unmount into a retry storm on exactly the screens that navigate fastest.
- **Truncated bodies (2026-07-25).** A body that dies mid-transfer makes `response.json()` throw a `SyntaxError` — a network failure wearing a parse error's clothes. `readBody` maps it to `NetworkError('transport')`; without that it surfaces as an unknown error and is never retried.
- **One retry layer (2026-07-25).** `isRetryable` is the single policy and it lives in the QueryClient predicate, deliberately not inside `apiFetch`. The predicate also stopped retrying 4xx entirely — the old one retried everything except 401, so a 404 burned three round trips before failing.
- **The 202 body (audio recover).** `202`/`204`/`304` short-circuit to `undefined` because `recoverAudio` returns 202 with an empty body, and parsing it as JSON throws on every success.
- **Only a server 401 marks the session expired.** A 500 does not — the backend having a bad day is not a dead session — and the no-local-session case never reaches the server because the fail-fast fires first. Marking is deliberately not acting: no auto-sign-out, because a server-side JWKS blip would bounce every user at once. `AuthGate` reads the flag and offers explicit re-auth.
- **The malformed enrichment URL (2026-07-25).** `getAlbumTracks` / `getArtistTopTracks` / `getArtistAlbums` built their query by string concatenation and produced `/albums&name=X` — a `&` where the first `?` belonged — whenever `limit` was omitted. All three now build through `URLSearchParams`. It is the concrete instance of the Property law above, and it shipped because the only input anyone tried had a `limit`.

## FINDINGS (pre-authoring, verified against the source)

- **The 15 s deadline does not cover the session refresh.** `apiFetch` awaits `authorization(path)` inside the `headers` object literal, *before* `startDeadline` is called ([index.ts:56-62](../../apps/mobile/src/shared/api-client/index.ts#L56-L62)). `authorization` calls `supabase.auth.getSession()`, which performs a network round trip whenever the access token needs refreshing — the exact call the weak-signal incident was about. So on a dying connection the request can hang inside `getSession` for as long as gotrue's own retry policy allows, with no bound from this slice, and the deadline that exists to prevent an unbounded spinner only starts once the refresh has already returned. To be confirmed against `@supabase/auth-js`' own timeout behaviour before calling it a defect.
- **A caller-supplied `Headers` instance is silently discarded.** `apiFetch` merges caller headers with `...(init?.headers ?? {})` ([index.ts:56-60](../../apps/mobile/src/shared/api-client/index.ts#L56-L60)). Spreading a `Headers` object yields `{}`, because its entries are not own enumerable properties — so a caller passing `new Headers({'Content-Type': 'application/json'})` loses every header without an error. Every current caller passes an object literal, so this is latent rather than live; recorded because the parameter is typed `RequestInit`, which admits `Headers`, and nothing rejects it.
- **Caller headers are spread last and can override `Authorization`.** Same lines. No caller does, and the two orderings trade "a caller can inject a different token" against "a caller cannot set a header the wrapper also sets". Recorded as observed, not asserted as a defect, because the security rule it brushes against is about the token not *leaking*, not about it being replaceable.
- **`audioRequestHeaders` ignores the session error.** It reads `data.session?.access_token` and returns `{}` when absent ([audio.ts:8-15](../../apps/mobile/src/shared/api-client/audio.ts#L8-L15)), where `apiFetch` distinguishes a transport failure from a dead session and marks the latter. The native player therefore makes an unauthenticated request, gets a 401 from the stream route, and nothing calls `markSessionExpired()` — so an expired session breaks playback with no re-auth offered, while every other surface offers one. The asymmetry may be deliberate (the player cannot surface an error the way a query can); it needs the consumer read before it is called a defect.
- **`fetchAudioUrls`' own 2500 ms abort is deliberately non-retryable.** Its `AbortController` is passed as `init.signal`, so `deadline.cancelled()` is true when it fires and `send` rethrows the raw `AbortError` — which `isRetryable` answers `false` for. That is the documented contract (a caller abort is a cancellation, not a timeout), but here the caller abort *is* a timeout, and the consumer, `pinnedStore`, lands the entry in `failed`. Recorded as observed behaviour with a real consequence, not as a defect.
- **`provider` is interpolated into six paths unencoded while `externalId` is encoded.** [enrichment.ts:31,45,59,70,167](../../apps/mobile/src/shared/api-client/enrichment.ts) and [discovery.ts](../../apps/mobile/src/shared/api-client/discovery.ts). Both values come from the same server-supplied `DiscoverySource`. Low risk today because providers are a closed set of identifiers, and recorded because the inconsistency reads as a decision when it is more likely an omission.
- **`_contentUrl` is the last string-concatenated query builder.** [enrichment.ts:12-15](../../apps/mobile/src/shared/api-client/enrichment.ts#L12-L15) — `getRelatedTracks` still builds `?limit=` by hand while its three siblings were converted to `URLSearchParams` after the 2026-07-25 malformed-URL defect. It happens to be correct because it has exactly one optional parameter, so there is no second `?` to get wrong. It is the shape the defect had, one parameter away from the same failure, and the leading underscore on a function with three live call sites reads as dead code.

## FINDINGS RESOLVED (authoring pass)

Sixteen findings came back from the seven blind authors, the cartographer and three assassin runs. Each was verified against the source before acting; **one source defect was fixed, one live cross-surface defect is carried as an `it.failing()`, and four proposed `it.failing()` markers were rejected.**

- **`provider` interpolated unencoded into six enrichment paths** (unit-5, and independently by the pre-authoring read) — confirmed and **fixed**. `externalId` in the same template was already `encodeURIComponent`'d, so the omission was visible and local. Providers are a closed set of plain identifiers, so encoding is a no-op for every value that occurs; what it closes is a `/` in a path segment silently re-addressing the request instead of failing. The regression tests were proved red against the pre-fix source.
- **`track_number` is computed, sent, and silently dropped by the server** (unit-7, via the derived contract) — confirmed and **fixed** (see the amendment below). The full chain: `toCreateTrackRequest` populates `track_number` on every save from a discovery result; Go's `CreateTrackRequest` DTO has no such field, so `encoding/json` discards it; `handleCreateTrack` never maps it into `AddTrackInput`, **even though `AddTrackInput.TrackNumber` exists and `add_track.go` already assigns it to the track**. The one missing link is the handler DTO and its mapping. The other path that could set it, `setTrackNumber`, has **zero production callers** despite `SetTrackNumberService` being implemented and unit-tested on the Go side. Net effect: a Track saved from an album context loses its position and the library counts 1..N instead of rendering real tracklist order — precisely what `track_number` was added to prevent. This is the run's headline defect and it is the class the programme says mutation testing provably cannot find: client-side the field is sent and ignored, so no mutation of the client changes observable behaviour.
- **`readBody`'s `304` arm is unreachable** (unit-1) — confirmed, **not a defect**. `apiFetch` throws on `!response.ok` first. The author's `it.failing()` was rejected: were the arm reachable it would return `undefined` into callers that immediately dereference the result, so the current behaviour is the safer one and the assertion should not be promoted. Replaced with a green test of actual behaviour; the arm is proposed for deletion and the nested `CLAUDE.md`'s `202`/`204`/`304` claim was corrected.
- **The unguarded wire cast** (unit-4 on `searchDiscovery`, unit-5 on `getLyrics`, unit-6 adjacent on `fetchAudioUrls`) — three independent reports of one design property, **seven proposed `it.failing()` markers rejected**. A well-formed body of the wrong shape surfaces as a bare `TypeError`. unit-4 cited this slice's own invariant — *"`NetworkError` covers … a truncated body"* — but a truncated body is one where `response.json()` **throws**, and that case is already handled at `index.ts:50-52`. The invariant does not reach well-formed JSON. Left as-is: the slice's answer to wrong-shaped data is the derived contract test, and hardening one of the three call sites while leaving the others is the worst available outcome. Now pinned by green tests asserting the actual contract, so the behaviour cannot change silently. **This is the open design question this slice hands forward.**
- **The 15 s deadline does not cover the session refresh** (pre-authoring) — **confirmed and carried, unfixed.** `apiFetch` awaits `authorization(path)` before `startDeadline` is called, and I verified against `@supabase/auth-js` that it imposes no per-request bound of its own: `_refreshAccessToken` bounds only its *retry* loop against a 30 s tick, and `_request` passes no `AbortSignal` at all. So a single hung refresh is unbounded, and the spinner the 2026-07-25 work existed to prevent is still reachable one step earlier. The fix is a design decision about where the deadline starts, not a QA-run edit.
- **`authorization()` interpolates Supabase's `error.message` unredacted** (unit-1) — **rejected, not a defect.** `AuthError` messages are fixed SDK strings and the access token is not in scope at that line. The proposed `it.failing()` demanded a redaction layer nobody plans to build, so it could never be promoted. The genuine green security assertions — token absent from URL, query string, thrown message and stack — were kept.
- **Caller headers are spread last and override `Authorization`** (pre-authoring; confirmed by an assassin survivor) — **behaviour unchanged, now pinned.** A caller-supplied `Authorization` wins over the wrapper's injected bearer token, which would bypass the fail-fast session check. No caller does it, and the mutation swapping the order survived in both directions until a test was added. Recorded as a footgun with the precedence pinned so it cannot change silently.
- **A caller-supplied `Headers` instance is silently discarded** (pre-authoring) — verified, **latent.** `...(init?.headers ?? {})` spreads a `Headers` object to `{}`. Every current caller passes an object literal; `RequestInit` admits `Headers` and nothing rejects it.
- **`audioRequestHeaders` ignores the session error** (pre-authoring) — verified, **left as observed.** It returns `{}` where `apiFetch` would distinguish a transport failure from a dead session and mark the latter, so an expired session breaks playback with no re-auth offered while every other surface offers one. Whether the native player *could* surface that is a playback-feature question, so the finding is recorded rather than settled here.
- **Ids interpolated raw into path templates** (unit-3, unit-6) — **recorded, deliberately not fixed.** Ten sites across `tracks.ts`, `playlists.ts` and `audioStreamUrl`. Unlike the provider case there is no local asymmetry to resolve, every id is a server-issued UUID, and encoding ten more sites is unrequested hardening on non-defective code. Proposed, the owner's call.
- **`fetchAudioUrls`' empty-array guard is dead** (cartographer, unit-6) — confirmed independently: `resolveLibraryUrls` returns early at `ids.length === 0`, and the other three callers pass a fixed one-element array. Proposed for deletion.
