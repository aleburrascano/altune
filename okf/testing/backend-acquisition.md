No new tests were written for this record — it is the twenty-category verdict over the module as it now stands. The mobile slice `okf/testing/shared-acquisition.md` (`resource:` the RN downloads-bar) is a different slice and is not touched here.

Re-derived after #52 extracted `execute`'s replace-exclusion setup (`configureReplaceExclusion`) and its dual failure branch (`reportAcquisitionFailure`) into named helpers: a structure-only, no-behavior-change refactor triggers no new category and needs no new test. The changed surface stays covered by the verdicts already recorded — Legacy / compat (the no-recorded-source replace path, `replace_test.go`), Failure injection (the mark-failed-and-publish branch, `acquire_test.go`), and Cross-surface contract (the `track_replace_failed`/`track_acquisition_failed` names stay literals at their `Publish` call sites).

This is an **orchestration-heavy, I/O-heavy** context whose entire input is untrusted provider output, so the environment family (Adversarial, Failure injection, Concurrency) carries most of the weight, and the pure `matching.go`/`failureReason`/`BuildAudioRef` core carries the Logic family. It owns no UI, no client cache and no aggregate, so the display and cache families reject cleanly.

## SELECTED

- **Table** — the pure, I/O-free core: `identityScore`, `metadataRank`, `channelScore`/`durationScore`/`categoryScore`/`viewScore`, `isTopicChannel`, `durationWithinTolerance`, `qualifierDistance`, `failureReason`, `sourceKey`, `buildSearchQueries`, `BuildAudioRef`/`sanitizePathComponent`. Boundaries are rows (the ≤3s/≤15s duration cliffs, the identity-60 gate, the tight-vs-loose window edges). `matching_test.go`, `step_download_verify_test.go` (`TestDurationWithinTolerance`), `variant_test.go`, `failure_reason_test.go`, `sourcekey_test.go`, `pipeline_stages_test.go`, `steps_test.go` (`TestBuildAudioRef`, `TestSanitizePathComponent`).
- **Cross-surface contract** — the module publishes two literal contracts the mobile client consumes: each `Step.Name()` string (`search`/`select`/`download`/`tag`/`store`/`update_track`) and each event name (`track_acquisition_started`/`_completed`/`_failed`/`_progress`, `track_replace_failed`). This side pins them as literals (`TestSearchStep_Name`, `TestSelectStep_Name`, `TestStoreStep_Name`, `TestUpdateTrackStep_Name`, `acquire_started_test.go`); the **derived** guardian — the test that reads these names out of the Go source at test time rather than restating them — lives on the mobile side (`shared/acquisition`'s `STAGE_TO_PHASE` contract test and `shared/events`' `eventContract` scan). The pair together satisfies the taxonomy's done-condition; the derivation is deliberately on the consumer.
- **Legacy / compat** — a track saved before its `AudioSourceURL` was recorded still reaches replace. `TestExecuteReplace_LegacyTrackSkipsTopRankedInsteadOfExcluding` and `TestSelectStep_SkipTopRanked*` (`replace_test.go`) cover the no-recorded-source path skipping the top-ranked candidate rather than excluding nothing, and `rejected_source_keys` only ever grows (`rejection_memory_test.go`).
- **Idempotence / replay** — three replay guards: the scheduler drops a second in-flight `Schedule` for the same track (`TestBackgroundScheduler_Schedule_DedupsInflight`), the 60s cooldown denies a second retry/reacquire (`TestCooldownGate_DeniesSecondCallWithinCooldown`, `TestHandleReacquire_Cooldown`, `retry_admission_test.go`), and `RejectAudioSource` is idempotent and bounded (`TestRejectAudioSource_IsIdempotentAndBounded`).
- **Adversarial** — the provider/disk trust boundary is the module's reason to exist. Wrong-recording rejection by AcoustID cluster (`fingerprint_test.go`), undecodable-bytes rejection at download and again at store (`step_download_verify_test.go`, `steps_test.go` `TestStoreStep_Execute_RejectsUndecodable`), the duration gate against previews/remixes/contaminated containers (`step_download_verify_test.go`), non-MP3 containers never ID3-tagged (`adapters/id3/tagger_test.go`, `step_tag_test.go`), and malformed inbound requests (invalid UUID → 400, unknown track → 404) in the handler tests.
- **Failure injection** — every I/O call site has a failing-path test. Search: one engine down, both down, no candidates (`steps_test.go`, `searcher_dualengine_test.go`, `registry_test.go`). Source panic recovered without failing the fan-out or crashing the process (`TestSourceRegistry_FindSurvivesPanickingSource`, `TestBackgroundScheduler_Schedule_RecoversFromPanic`). Download error cleans the temp dir (`step_download_test.go`), store error surfaces (`steps_test.go`), tagger error is swallowed (`step_tag_test.go`), prober/identifier fail open (`fingerprint_test.go` `TestDownloadStep_IdentifierErrorIsFailOpen`, `step_download_verify_test.go`), resolver error is non-fatal (`identity_test.go`), track-not-found is handled (`acquire_test.go`, `steps_test.go`).
- **Concurrency / ordering** — the scheduler semaphore bounds parallelism (`TestBackgroundScheduler_ScheduleMultiple_RespectsSemaphore`), in-flight dedup, panic isolation per goroutine, and post-shutdown no-op (`scheduler_edge_test.go`); the registry fan-out writes each source into its own slot so merge order never depends on completion order (`TestSourceRegistry_FindMergesStampsAndDedupesByURL`, `TestMergeSlots_*`); `rankCandidates` breaks ties deterministically (`TestRankCandidates_TieIsDeterministicAndPrefersExpectedLength`, `TestRankCandidates_TotalTieIsStillDeterministic`); the status snapshot is a copy (`TestAcquisitionStatus_SnapshotIsACopy`); pipeline steps run in order and roll back in reverse (`buildsteps_test.go`, `pipeline_test.go`); a package-wide goroutine-leak check runs via `leak_test.go`'s `TestMain`.
- **Security** — `failureReason` is asserted to drop internal error detail so no raw error chain — which can carry a cookie path or a filesystem layout — reaches the `Track` row or the wire (`TestFailureReason_DropsInternalDetails`). This is the taxonomy's "asserted absent from error payloads"; the AcoustID key and yt-dlp cookies themselves live in adapter config, outside this slice's logic.
- **Functional / acceptance** — the public HTTP surface asserted through `httptest`: retry and reacquire status codes (202 accept, 409 wrong-state, 429 cooldown, 404 missing, 400 malformed, 401 unauthenticated) in `retry_handler_test.go` / `reacquire_handler_test.go`; and the product promise itself — "the stored file is the recording the user saved" — gated per failure class by the `service/eval/` golden harness against `cmd/acquisitioneval`'s committed baseline (`harness_test.go`, `TestEmbeddedSuiteMatchesCommittedBaseline`).
- **Invariant / architecture** — mechanically-enforced CLAUDE.md rules: import direction (acquisition never reaches catalog's adapters or the composition root) via `.golangci.yml` depguard in CI; the single `CoreSteps` assembly pinned by `TestBuildSteps_RunsAllSixInOrder`; provenance set only through the guarded setter (`TestSetAcquisitionProvenance_RejectsUnknownValues`); and the eval baseline gate, which fails CI on any selection change that regresses a failure class.
- **Regression** — the module's irreplaceable memory of shipped incidents: the matching corpus (`matching_regression_test.go`), Topic-beats-SoundCloud (the rollback that forced cluster-over-MBID comparison — `matching_soundcloud_test.go`), acoustic/music-video losing to the master on the same channel (`variant_test.go`), and undecodable-m4a rejected at store (the shipped-m4a defect, F9 in `ARCHITECTURE.md §1` — `steps_test.go`, `step_download_verify_test.go`).

## REJECTED

- **Derivation** — no rendered component in a Go backend; the display/gating logic the category targets does not exist here. The gates that *do* decide what enters the library (identity, duration, fingerprint) are already pure functions covered under Table and Adversarial.
- **Reducer** — acquisition owns no store and no `(state, event) → state` aggregate. The `Track` lifecycle (`MarkReady`/`MarkFailed`/`RevertToPending`) belongs to `catalog/domain` and is a reducer *there*; this module is its customer. The admission gate and job counters are covered under Idempotence and Concurrency.
- **Property** — no generated/property harness on the Go surface (the taxonomy notes Go has no `fast-check` equivalent beyond stdlib fuzzing, and none is wired here). The ranking invariants that would justify one — determinism under permutation, Topic-always-first — are instead pinned by the eval golden corpus and the deterministic-tie table tests. Reopen with a `go test -fuzz` pass over `qualifierDistance`/`identityScore`; see DEFERRED note below.
- **Persistence round-trip** — this slice persists only through catalog's `TrackRepository` port; the durable DB round-trip is catalog's persistence-adapter integration test, not this module's. The write-happened side effect (`MarkReady`, duration, `rejected_source_keys`) is asserted against the fake in `TestUpdateTrackStep_PersistsTheRejectedSources`. The slice's own state — `jobLog`, the admission maps — is deliberately in-memory and resets on restart (`ARCHITECTURE.md §7.9`), so there is no on-disk shape to round-trip.
- **Invalidation** — no client-side query cache in the backend. Acquisition emits SSE events; the mobile `shared/events` `INVALIDATION_MAP` owns cache refresh.
- **Liveness** — no rendered component; the live progress signal is the `track_acquisition_progress` SSE event, whose emission is covered under Cross-surface contract and Failure injection (`scheduler_progress_test.go`, `job_telemetry_test.go`). Rendering it live is the mobile slice's Liveness.
- **Timing / dwell** — no user-visible duration is held here. The 60s retry/reacquire cooldown is an admission *window* (tested via injected clock offsets under Idempotence/Table — `TestCooldownGate_AdmitsAfterCooldownElapsed`), not a dwell a user watches elapse; the pipeline's 10-minute and 30-second rollback budgets are timeouts, not dwells.
- **Accessibility** — no user-facing UI in the backend.

## DEFERRED

- **Device e2e** — the acquisition spine crosses live providers (yt-dlp/SoundCloud), ffmpeg/ffprobe, AcoustID and the database; no live-provider or device lane runs in CI. The `service/eval/` harness runs the real `CoreSteps` in-process but every golden is hand-authored, not a captured live yt-dlp result (`ARCHITECTURE.md §7.8`, "Still open"). Unblocked by capturing real yt-dlp candidate lists as goldens or standing up a live-provider integration lane; tracked at programme level, not reopened per-slice.

## MUTATION AUDIT

Not run for this record. No mutation harness is wired on the Go surface in this repo (no `go-mutesting`/Stryker equivalent; the taxonomy's `npx stryker`/`fallow`/`react-doctor` tooling is mobile-only). Until one is, the standing proxy for "do these tests constrain rather than merely execute" is two-fold and both are CI-gated:

- the `cmd/acquisitioneval` baseline gate — a behavioral mutation catch at the selection layer: any change that regresses a failure class from `ARCHITECTURE.md §1`'s table fails the build (`TestEmbeddedSuiteMatchesCommittedBaseline`, `TestRegressions_FlagsOverallAndPerClassDrops`);
- the `matching_regression_test.go` corpus, which fails the moment a ranking change re-admits a previously-rejected wrong recording.

A scoped Go mutation pass over the pure core (`matching.go`, `failureReason`, `BuildAudioRef`) is the recommended unblock, and is where a survivor would most likely hide.
