SLICE: `apps/mobile/src/shared/telemetry/`
TAXONOMY: [test-taxonomy](../playbooks/test-taxonomy.md)

Slice 7 of the [test-hardening programme](../../docs/specs/test-hardening/plan.md). Rebuilt blind on 2026-07-31: authors were given the source, the types it imports, and the taxonomy only — no `okf/`, no deleted tests via git, no nested `CLAUDE.md` test list.

Five files, 5.6 KB, **0% covered on every metric before this run** — the only slice in the programme to start at a flat zero across all four numbers. Nothing in the repo executed a line of it: the five production consumers all live in feature slices that have no tests yet, and the two test files that mention telemetry (`shared/api-client/__tests__/invariants.test.ts`, `__tests__/harness.test.ts`) only grep its source text or exercise the filesystem double directly.

What makes the zero worth more than its line count: this is the slice that owns the app's **second durability guarantee**. ADR-0020 was written about the first one — the `expo-file-system` double's `write() {}` made `outboxStore.persistOutbox` unassertable, and inverting it so a non-empty queue *deleted* its own file left the whole suite green. That inversion now turns nine tests red, checked by hand. Everything downstream of a lost `library_add` is a lost relevance label for the behavioral eval corpus, and nothing about the loss is visible to the user or to the app — which is exactly how the two live defects this run found had been shipping unnoticed.

## SELECTED

- **Table** — five pure functions with branches: `advanceSession`'s rotate/keep arms at the exact `SESSION_INACTIVITY_MS` boundary (`>` not `>=` — the equality case is a row), `capEntries`'s `<= max` boundary at `max-1`/`max`/`max+1` and `max === 0`, `dedupeById`'s last-wins collision, `withEnvelope`'s field overwrite when the incoming event already carries an `event_id`, and `outboxStore.loadPersistedOutbox`'s four early-return arms. `__tests__/session.test.ts`, `__tests__/outbox.pure.test.ts`, `__tests__/outboxStore.test.ts`.
- **Reducer** — `advanceSession(state, now)` is literally a `(state, event) → state` function, and `_queue` is a module-global store with four transitions (`restore`, `enqueue`, `commit-after-send`, `cap/dedupe`). Every state × transition pair the domain permits is a case: enqueue onto empty / onto full / onto a queue holding the same `event_id`; flush from empty / mid-drain failure / full drain; restore before and after the first enqueue. `__tests__/outbox.test.ts`, `__tests__/session.test.ts`.
- **Property** — `fast-check` laws over spaces too large to enumerate: `capEntries` never returns more than `max` and its output is always a **suffix** of its input (the oldest are what drop); `dedupeById` output length equals the distinct `event_id` count and every id maps to the *last* entry carrying it; `advanceSession` always returns `lastActivity === now` regardless of arm, and rotates if and only if the gap exceeds the constant; `makeEventId` always matches the RFC4122-v4 shape and never collides across a large sample. `__tests__/outbox.property.test.ts`, `__tests__/session.test.ts`.
- **Cross-surface contract** — the strongest seam in the slice. `DiscoveryEventType`, the envelope field names, and the payload value types are all consumed by Go, and all three are **derived from the Go source at test time**, never restated as literals: the event-name set is scanned out of `services/go-api/internal/discovery/domain/events.go`, the client-submittable subset out of `ClientSubmittable()`, the wire field names out of `DiscoveryEventRequest`'s json tags in `services/go-api/internal/discovery/adapters/handler/search_endpoints.go`, and the payload type constraints out of `validatePayloadTypes` in `services/go-api/internal/discovery/service/record_event.go` (which requires `session_id` to be a **string** — the one payload key this slice itself writes). This is the `shared/events` `eventContract.test.ts` pattern applied to the third seam. `__tests__/eventContract.test.ts`.
- **Legacy / compat** — `critical-outbox.json` is written by one app version and read by the next. Every historical and partial shape has a fixture: absent file, empty file, empty array, an entry missing `client_occurred_at`, an entry carrying an unknown extra key, a `payload` of `null`, and the pre-durability case where no file exists at all. `loadPersistedOutbox`'s filter exists precisely because a partial write must not poison the flush loop. `__tests__/outboxStore.test.ts`.
- **Persistence round-trip** — the category ADR-0020 exists over. A real double round-trips: `persistOutbox(entries)` → `loadPersistedOutbox()` returns what was written, byte-identical in content; deleting the write breaks a test; **inverting the empty/non-empty arms breaks a test**; and the drain-to-empty path deletes the file rather than leaving a stale one to resurrect an already-sent event on next cold start. `__tests__/outboxStore.test.ts`.
- **Idempotence / replay** — every input here can be delivered more than once. `enqueueCritical` with the same `event_id` twice yields one entry (`dedupeById` last-wins); `flushOutbox` re-entered after a completed drain is a no-op; `persistOutbox` applied twice equals once; `loadPersistedOutbox` is pure over an unchanged file; and a restore that merges disk into a queue already holding the same id does not double it. The server's `ON CONFLICT (event_id) DO NOTHING` is the other half of this contract and is why the client is allowed to retry at all. `__tests__/outbox.test.ts`, `__tests__/outboxStore.test.ts`.
- **Adversarial** — the on-disk JSON is a trust boundary as real as the network one. Cases: non-JSON bytes, valid JSON that is an object rather than an array, an array holding `null`/numbers/strings/nested arrays, entries with a numeric or absent `event_id`, an entry whose `event_id` is the empty string, and a `__proto__`-carrying entry. Plus the server side: a 400 (the type the server rejects), a 401, a 500, and a truncated body, each of which must degrade rather than throw into a fire-and-forget caller. `__tests__/outboxStore.test.ts`, `__tests__/recordEvent.test.ts`.
- **Failure injection** — every I/O call site fails in at least one test. Disk: `createDirectory`, `write`, `read` and `delete` each injected via the `expo-file-system` double's `__fs.failNext(kind)`, asserting the documented invariant that a disk failure degrades to in-memory-only and **never throws** into `void enqueueCritical(...)`. Network: transport failure, timeout, and non-2xx via the `fetch` double, asserting `flushOutbox` stops at the first failure and leaves the remainder queued. `__tests__/outboxStore.test.ts`, `__tests__/outbox.test.ts`, `__tests__/recordEvent.test.ts`.
- **Concurrency / ordering** — the two hazards the 2026-07-29 audit named. The `_flushing` reentrancy guard has a test that fails without it (a second `flushOutbox` entered while the first is mid-await must not double-send), and the commit-**after**-send ordering has a test that fails when the two lines are swapped (an entry must not leave disk before its POST is confirmed). Also driven: an `AppState → active` transition arriving during an in-flight flush, and two `enqueueCritical` calls interleaved on the same tick. `__tests__/outbox.test.ts`.
- **Security** — the slice writes user-derived content to plaintext disk and mints an id that is *not* a security token. Asserted: no auth material ever reaches `critical-outbox.json` (the persisted file's key set is exactly the envelope's), no file in the slice imports `expo-secure-store` or the Supabase client or reads an access token, `session_id` is not derived from any credential, and the slice writes no secret into a query key. The `Math.random`-based `makeEventId` is asserted as a *dedup* key, never as an unguessable one. `__tests__/slice-invariants.test.ts`.
- **Functional / acceptance** — two user-visible promises, asserted through the public interface in `docs/ubiquitous-language.md` terms. **Two-tier reliability**: a label-critical event (`library_add`, `wrong_album`) survives a hard app kill — enqueue while the network is down, discard the module state, restore in a fresh module instance, and the event still delivers. **Telemetry is never surfaced to the user** (ADR-0007 §3.12): every failure path — disk, network, malformed response — resolves rather than rejects, and `useRecordEvent`'s error arm reaches `console.warn` and nothing else. `__tests__/outbox.restore.test.ts`, `__tests__/useRecordEvent.test.tsx`.
- **Invariant / architecture** — four written rules over this slice are mechanically checkable and now checked in CI: `library_add` and `wrong_album` go through `enqueueCritical` and never through `useRecordEvent` (asserted against the feature tree, so a future call site that takes the fire-and-forget path fails the suite); the dependency direction is one-way telemetry → api-client, never back; no `console.log` in the slice; and the banned noun `song` appears in no identifier or string literal. `__tests__/slice-invariants.test.ts`.
- **Regression** — every defect this run confirmed carries a test that fails against the pre-fix source and passes after. See the defect list below.
- **Mutation audit** — see below.

## REJECTED

- **Derivation** — no display or gating state is computed anywhere in the slice. There is no component, no rendered output, and nothing that decides what shows or what unlocks; `useRecordEvent` returns a mutation object and renders nothing. The category's prescribed first step — extract the derivation to a pure function — is already the slice's structure (`advanceSession`, `withEnvelope`, `capEntries`, `dedupeById`), and those are Table and Property rows.
- **Invalidation** — the slice performs no cache mutation. `useRecordEvent` is a `useMutation` with no `onSuccess`, no `queryClient`, and no key; telemetry deliberately never refreshes server state, because an event write has no read side on the device. Nothing here can invalidate the wrong entries because nothing invalidates anything.
- **Liveness** — no rendered output. The category fires on the *consumers* (a save that emits `library_add` also flips a row), and that obligation belongs to `features/detail` (slice 9) and `features/playback` (slice 11), not here.
- **Timing / dwell** — no duration is user-visible. `SESSION_INACTIVITY_MS` is a 30-minute correlation window with no UI expression: nothing is held on screen, nothing expires visibly, and no user can observe the rotation. The one duration this slice *carries* (`payload.dwell_ms`) is computed in `features/playback` and passed through opaquely. The boundary itself is a Table row, which is the correct home for a threshold nobody watches.
- **Accessibility** — no component, no interactive element, no announcement.
- **Device e2e** — deferred to the spine flow rather than to this slice, on the same terms as the six slices before it. Every path here is reachable in-process; what a device would add is the native `AppState` transition, and that is the programme-level "device smoke of the event stream" item already carried in the plan's Outstanding list.

## DEFERRED

None. Every category is either satisfied at its done-condition or rejected above with the property of the code that rules it out.

## DEFECTS FIXED

**Two live cross-surface breaks, both invisible by construction**, because `useRecordEvent` swallows every failure to `console.warn` and the outbox swallows its own. Best-effort telemetry means the *user* never sees a failure; it does not mean nobody does. Both had been shipping for over a week.

1. **`result_signature: null` 400s, and a 400 used to block the critical outbox forever.** `DiscoveryResult.result_signature` is optional on the wire, and four call sites coerced its absence to `?? null` — `useSaveTrack`, `useReportWrongAlbum`, `useDiscoverLogic`, `playback/signals.ts`. Go's `validatePayloadTypes` rejects a *present* `result_signature` that is not a string, and JSON `null` unmarshals into `map[string]any` as `nil`, so the server answers `400 payload.result_signature must be a string` (confirmed by probe: null → 400, string → 204, absent → 204). The two fire-and-forget sites lost their events silently. The two critical sites did something worse: `flushOutbox`'s `catch { break }` treated a permanent 400 exactly like a transient network drop, so the rejected entry stayed at the head of the queue and **every `library_add` and `wrong_album` queued behind it became undeliverable** — a total failure of the label-critical tier, which is the one guarantee this slice exists to provide. Fixed on both sides: the four producers omit the key instead of nulling it, and `flushOutbox` drops an entry rejected with 400 and keeps draining. The classifier is deliberately narrow — only `ApiError(400)`. A 401 is retried, because `apiFetch` throws 401 whenever the Supabase session is momentarily absent and dropping on that would invent a new loss path in the very tier being protected.
2. **`results_shown` was rejected as server-reserved, so impression telemetry never existed.** Covered in the concept doc; the whitelist's premise was wrong for that one type and no server code ever emitted it. Fixed server-side.

**One in-slice hardening.** `loadPersistedOutbox` admitted an entry whose `event_id` is the empty string — a valid `string`, but not a usable id. `dedupeById` keys a `Map` on it, so several such entries collapse into one: silent loss of exactly the labels the filter exists to protect. The guard now requires a non-empty id. This is the slice-6 rule applied again — a validator taking `unknown` must not admit what it cannot validate.

## MUTATION AUDIT

Two mechanisms, as ADR-0020 requires, and the harness itself turned out to be the third finding.

**`test-assassin` — 51 semantic mutations across three sequential passes**, grouped by source file, never concurrent. Seven survived the first sweep; all seven were weak tests rather than source defects, and all seven are now dead:

| pass | target | applied | killed | survived → fixed |
|---|---|---|---|---|
| 1 | `outbox.ts` | 20 | 14 | 2 (+4 equivalent) |
| 1b | `outbox.ts` re-run | 11 | 9 | 1 (+1 equivalent) |
| 2 | `outboxStore.ts`, `recordEvent.ts` | 20 | 15 | 2 (+3 equivalent) |
| 3 | `session.ts`, `useRecordEvent.ts` | 20 | 18 | 2 |

The two that matter most: **`_restored = true` was removable** — without the latch, `ensureRestored` re-merges the disk on every call, so an entry left behind by a failed delete is resurrected and re-sent *within the same session*, no restart required; and **`e === null` was removable from `loadPersistedOutbox`'s type guard** — `typeof null === 'object'`, so a stray `null` reaches `.event_id`, throws inside `.filter()`, and the outer `catch` discards **the entire backlog** rather than the one bad element. Every existing adversarial fixture seeded arrays where *every* element was invalid, so `[]` was the expected answer either way and nothing could tell per-element filtering from a whole-array abort.

The first sweep measured **91.36%** with fourteen survivors. Four were real gaps and were closed; the remaining **ten are equivalent, each checked against the replacement Stryker actually applied** rather than the stronger mutation it resembles — the trap slice 6 recorded:

One of those four is worth keeping for the method rather than the fix. The test written to kill `_state = { … }` → `{}` **passed against the mutation**, and the second Stryker run caught it: the test emitted the foreground transition *before* its first `getSessionId()` call, but `ensureForegroundRotation` registers the listener from inside `getSessionId`, so no listener existed yet and the mutated line never executed. A test that drives a lazily-registered listener must first call the thing that registers it. Nothing about the test looked wrong; only re-measuring exposed it — which is the argument for running the mutation audit *after* every repair, not once.

- `c === 'x'` → `false` and `'x'` → `''` in `makeEventId` (2 mutants). Every character then takes the `(r & 0x3) | 0x8` branch, so ids draw from `8-b` instead of `0-f`. Still RFC4122-v4-shaped, still 4³² combinations, and the id is a **dedup key, not a security token** — a property this slice asserts explicitly. Equivalent for the contract the value actually has; killing it would mean asserting the quality of `Math.random`.
- `entries.length <= max` → `<` in `capEntries`. At exactly `max`, `entries.slice(entries.length - max)` is `slice(0)` — same content, same freshness as `[...entries]`. The two branches converge precisely at the boundary.
- `_queue.length === 0` → `false` in `flushOutbox`'s guard. The `_flushing` half is untouched and the `for` loop over an empty array does nothing; the only difference is that `_flushing` briefly toggles, which nothing can observe.
- `_restored = true` → `false` inside `_resetOutboxForTest`. Test-only scaffolding with no production caller; asserting it would be asserting the semantics of the test seam itself.
- `{ intermediates: true }` → `{}` and `true` → `false` in `outboxFile` (2 mutants). `intermediates` only matters when a parent segment is missing, and the only parent is `Paths.document`, the OS-provisioned sandbox root, which always exists.
- `!Array.isArray(parsed)` → `false`. Every non-array shape `JSON.parse` can return lacks `.filter`, so the call throws into the same outer `catch` and yields the identical `[]`.
- `typeof e !== 'object'` → `false`. Only the *first* disjunct is dropped, so `|| e === null` still rejects nulls; every surviving non-object reads `.event_id` as `undefined` and is filtered by the id check downstream. The downstream guard absorbs it entirely.
- `file.exists` → `true` before `file.delete()`. The native call throws on a missing file, but the throw lands in `persistOutbox`'s own `catch {}` and the function returns normally either way — the delete was a no-op in both worlds.

**The harness was hiding a guard in five slices, not one.** `Directory.create()` throws when the directory already exists unless `idempotent: true`, and the source correctly passes `{ intermediates: true }` behind an `if (!dir.exists)` check — but the `expo-file-system` double modelled `create()` as an idempotent set-add, so dropping that guard left the suite green. The same guard appears at five call sites across the app (`pinnedFiles`, `pinnedStore`, `audioPrefetch`, `themePreference`, `outboxStore`), and `shared/offline` had already been hardened to a 92.71% kill rate *with this hole open*. The double now throws to match the native contract, constrained by two new `harness.test.ts` cases; the full 1,390-test suite stayed green, so nothing was leaning on the forgiving behaviour. The same shape appeared twice more in-slice: the inline `AppState` mocks ignored the event *name*, so `addEventListener('change', …)` → `addEventListener('', …)` was invisible until the mocks were taught to filter on it. **A double that cannot express a failure hides it from every slice that shares the double, not only the slice being measured** — which is the second time this programme has learned it, after `write() {}`.

Coverage: **0/0/0/0 → 100/100/100/100**, per file and in aggregate — the third slice after `shared/api-client` and `shared/lib` where the per-file minima and the aggregate coincide, so the ratchet records what every file actually holds rather than an average hiding a floor breach. This slice is also the first to start at a flat zero on all four metrics.
