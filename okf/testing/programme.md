This concept is the programme's rationale and its ledger. The skills carry the instructions; nothing here is an instruction.

## Why this exists

The starting question was whether Robert Martin's position — *"I do not read the code my agents write; instead I surround them with extreme constraints: unit tests, gherkin tests, QA procedures, quality metrics, mutation testing, test coverage"* — is workable here. Not reading agent-written code is only defensible if the constraints are strong enough that passing them *means* something. So the honest first move was to measure the constraints rather than add more.

An agent-driven mutation pass on 2026-07-29 ran 72 mutations against six `apps/mobile/src/shared/` subsystems, under a suite of **552 passing tests**. It killed 26. **A 38% kill rate**: roughly two-thirds of what the suite executed, it did not constrain. Coverage counted every survivor's line as covered.

The suite was not careless — zero snapshot tests, dense assertions, one genuinely excellent cross-surface contract test. Three pieces of *infrastructure* were hiding untested code:

- Module-wide `jest.mock` of a whole file removed it from execution entirely, while coverage still reported the module.
- The `expo-file-system` double had `write() {}`, unwired from `textSync()`. **No test could observe persistence at all**, so both of the app's durability guarantees (offline pins, critical telemetry) were unassertable. Gutting `pinnedStore.saveIndex` and inverting `outboxStore.persistOutbox` each left the suite green.
- A single global `coverageThreshold` blended per-file zeros into one average nobody inspected.

Meanwhile nothing in CI ran the mobile suite at all, and neither shipping path ran any check: `deploy-backend.yml` raced its own test workflow on the same push, and a `v*` tag matched no test trigger, so every `.ipa` shipped unverified.

The deeper problem was that no artifact answered *which constraints a piece of code deserves*. Coverage answers "did this line run." Nothing asked "is this the right set of tests, and do they hold."

## The six decisions

**1. A twenty-category test taxonomy** ([test-taxonomy](../playbooks/test-taxonomy.md)), in six families, each category carrying the code property that triggers it, what it proves, and a checkable done-condition. Applicability is *derived* from a property of the code, not from judgment about what feels worth testing. Every category cites the concrete survivor or written rule that justifies it, so the list is derived from this codebase rather than imported.

**2. Per-slice selection records** committed under `okf/testing/`, recording every category as selected, **rejected with a reason**, or deferred. A reasoned rejection is a finding; a silently omitted category is indistinguishable from a hole — which is exactly how a slice kept a green suite that never exercised two of its fourteen event types.

**3. Rebuild blind.** Authors receive the source and the taxonomy only, and are barred from `okf/` (except the taxonomy), from recovering deleted tests via git, and from any `CLAUDE.md` test list. A prose-guided author reproduces the blind spots of whoever wrote the prose. Blind authors are also required to report source defects without fixing them.

**4. Ratchets, not bars.** Per-glob coverage floors, a Stryker mutation-score floor, and count ceilings for static analysis — all raise-only. This is what makes an imperfect codebase gateable today instead of after a stop-the-world cleanup.

**5. Both mutation mechanisms, for different jobs.** Stryker gives a reproducible number a ratchet can stand on. `test-assassin` gives the semantic mutations no generator produces — a swapped adjacent field, a reversed spread so the stale copy wins, a commit before its send — which found the worst defects in the audit.

**6. A test asserts intended behaviour, never a defect.** On finding a bug: fix the source, or mark the test `it.failing()`. A passing test that encodes broken behaviour protects the defect.

## What generalises

**Mutation testing and blind derivation find disjoint defect classes.** Mutation asks *"would the suite notice this change?"* and so finds weak tests over correct code. Blind derivation asks *"is this right?"* and so finds wrong code. The `failure_message` defect proves they cannot substitute: the field is never sent, so replacing its read with `null` is an *equivalent* mutation that no runner can surface. Both are required.

**A gate is not proven by passing.** Four separate things looked like gates and were not: react-doctor ran advisory; the filesystem double could not round-trip; `fallow dead-code` exits 0 even with an `error`-severity finding, so `--fail-on-issues` is what actually gates; and `tsc` was *stronger locally than in CI*, because expo-router's generated types are gitignored. Each was invisible until forced to run for real.

**A test that selects a branch does not constrain it.** Slice 8's web-fallback test needed three versions. The first crashed Jest workers, so unrelated mutants scored as errors rather than kills. The second stopped the crashes but made all five condition mutants *survive*, because both arms answered `null` for an unwritten key. Only the third — asserting the arms **disagree** — killed them. Coverage counted the arm as covered in all three.

**A double that cannot express a failure hides it from every slice at once.** `Directory.create()` throws when the directory already exists unless `idempotent: true`; the double modelled it as an idempotent set-add, so `if (!dir.exists) dir.create(...)` was removable with the suite green in five separate places. Slice 7 tightened it. Read every completed slice's kill rate with this in mind — `shared/offline` was already hardened at 92.71% and this survived it. Conversely, a harness fix raises every slice that shares the harness: that same tightening took `shared/offline` 92.71 → 93.12 **with no test written for it**.

## The incidents behind the rules

Each rule the skills carry was paid for once.

- **Two assassins against one working tree.** They share the suite, so each runs it while the other has a mutation applied. Survivors stay trustworthy — a concurrent mutation can only add failures — but every *kill* becomes unattributable, and a kill rate is the number this programme reports. Slice 4 discarded both agents' attributions and re-ran all 98 mutations sequentially.
- **An unhandled rejection in a test of a fire-and-forget API.** `void enqueueCritical(...)` is fine while the source is correct, but Stryker's `BlockStatement` mutator empties a function body, so `withEnvelope` returned `undefined`, `enqueueCritical` rejected, and the rejection was unhandled — which under Node 25 kills the *worker* rather than failing the test. Stryker abandons the whole run after a handful of child-process crashes, so a mutant that should have been a clean kill aborted the measurement at 32%.
- **A source-scanning test reading `__dirname`.** Stryker runs from a sandbox copy with every mutant switch inlined, so a contract test that regex-matches a source shape matches in `jest` and fails the *dry run* under `stryker` — which aborts before a single mutant is applied and reports it as a config error rather than a test failure. Slice 7 lost two Stryker runs to this.
- **Taking a verdict from output text instead of an exit code.** Slice 4's first gate-proof harness grepped the runner's summary and reported a gate as biting when it was not; the mutation actually survived. Two mutation results in that run were also silently wrong because a 4-space anchor matched inside a 6-space line elsewhere in the file — the mutation applied to a different call site than the one it was labelled with.
- **Findings that live only in a chat transcript are lost at the end of the session.** `okf/testing/shared-acquisition.md` exists because eight verified survivors nearly were.
- **Stryker's sandbox inside `rootDir`.** Jest collects the sandbox's own test copies and silently doubles the suite. `tempDirName` is `../../.stryker-tmp` for this reason.
- **A worktree has no generated expo-router types and no `node_modules`.** `.expo/types/router.d.ts` is gitignored, so `useSegments()` loses its typed tuple and `tsc` fails with a bogus `TS2493`. And Stryker's sandbox discovery uses `readdir` Dirents, where a junction reports as a link rather than a directory — it logs `Could not find a node_modules folder to symlink`, then every mutant dies with `Cannot find module 'jest'` and the run is reported as a config error. Both are why the worktree setup copies the types and builds `node_modules` as a real directory of junctioned children.

## Alternatives rejected — do not re-propose

**Trust the suite and stop reading the code.** The original proposition. Rejected because 38% is not a base to stop reading over. The stance becomes defensible only once the done-conditions hold and the kill rate is high — it is an *outcome* of the programme, not its premise.

**Keep the existing suite and add to it.** Tempting, and it was argued for: the 26 kills were real constraints and the incident-regression tests encoded production bugs. Rejected on the owner's call, and the risk was mitigated by harvesting: the findings and rationale largely already lived in `okf/`, and the rest were written into `okf/testing/` before deletion. The blind rebuild also turned out to be *better* than an additive pass, because it found nine defects an author reading the old tests would have inherited blind spots about.

**Refactor for testability first.** The instinct was that code shape was the obstacle — mixed logic in single functions, insufficient decomposition. The mutation data refuted it: every survivor sat in a function already small and pure enough to test exhaustively. `if (prev >= 0)` is as simple as a condition gets and it survived, and extracting it to `canStepBack()` would not have killed the mutant — only an input at `currentIndex === 1` does. Decomposition changes where logic lives, not which cases are exercised. Extraction is justified only where it changes *reachability* (a derivation trapped inside a component), never to raise a count.

**Optimise lines of test code.** Rejected because it selects against the strongest techniques: one `fast-check` property is a handful of lines and constrains an unbounded input space, where the equivalent hand-written table is ten times longer and covers only the rows someone thought of. The meters are kill rate and categories-satisfied.

**Chase 100% mutation score.** Rejected. Of 56 survivors in the first `shared/events` run, roughly eight named real defects; the rest were guard-clause conditionals and error-message strings, and this repo's own convention forbids asserting error copy, making those equivalent by rule. Triage and record, do not chase — an unexplained number is the coverage trap in a new costume.

**Visual-regression / screenshot diffing.** Rejected as a category, documented in the taxonomy so it stays rejected. Its failure mode matches snapshot tests: when the baseline breaks the cheap fix is to regenerate it, which under agent authorship is what happens.

**Clear the static-analysis backlog before continuing.** 137 fallow complexity findings and 106 react-doctor warnings. Rejected: they are already ratcheted so they can only fall, they span slices whose code will be restructured as those slices get tested, and acting on "split this high-impact file" before that slice has tests is the refactor-first mistake again.

**Lower a floor to make a batch land.** Rejected by construction — see the backend entry under Outstanding for the one lowering on record and why it is not a precedent.

## Costs accepted

~24 documentation files touched per slice deletion, because of the `okf/` and `CLAUDE.md` staleness hooks. A doubled backend test run on pushes to `main`, so `test-backend.yml` stays the independent record that main is green. A mutation run measured in minutes, which is why it is nightly rather than per-PR.

## Outstanding

- **The backend coverage floor was lowered 65 → 62 on 2026-07-31, and owes a ratchet back.** `test-backend.yml`'s ratchet had been failing for at least eight consecutive runs (62.1% → 62.2% → 62.4%) without blocking anything, because that workflow and `deploy-backend.yml` fired on the same push and ran in **parallel** — the deploy never waited for the verdict. `cb26d1c` (2026-07-30) made the deploy `needs: test`, and the very next backend push, an unrelated audio-versioning fix, was the first thing the floor had ever actually stopped. The floor was lowered to 62 to let that deploy through; the coverage did not move and the code was not at fault. **This is the one lowering on record and it must not become a precedent** — the repo's rule everywhere else is raise-only, and a floor that yields on demand is not a gate. Where the missing 3pp lives, by uncovered-function count: `discovery/adapters` (245), `discovery/service` (85), `catalog/adapters` (77), `acquisition/service` (60). The adapter packages are the bulk and the least testable without a database — `catalog/adapters/persistence/track_repo.go` is 0% end to end — so the cheap wins are in the two `service` packages, which are pure logic behind ports. Ratchet 62 → 65 as those land, and delete this entry when it clears.
- **The per-glob coverage floors are enforced per *file*, not per glob — and the gate is currently red.** A glob key like `'src/shared/events/**'` makes Jest apply the threshold to every matching file individually, not to their aggregate. Slice 1 recorded 97/90/100/100 as though it were an aggregate, and two of its own files sit below that: `sse-client.ts` (96.24% stmts / 85.71% branches) and `trackCachePatch.ts` (94.93% / 78.12%). So `npx jest --coverage --ci` — the exact command in `test-mobile.yml` — has been failing since slice 1 landed, on slice 1's own floor. Confirmed independent of slice 3 by zeroing the playback floor and re-running. Two ways out, both someone's call: bring those two files up to the committed floor, or split the ratchet into per-file entries that record what each file actually holds. **Do not** lower the events numbers to fit — that is what raise-only forbids. Slice 4 re-confirmed these two events files are still the *only* per-file breaches in the repo.
- **`stryker.config.json`'s ceiling is about UI-bearing slices, not about adding slices.** It has one `mutate` glob and one global `thresholds.break`, raise-only. `shared/acquisition` measures 79.44%, dragged down almost entirely by `StyleSheet`/`Animated`-config mutations in its two presentational components, which this repo's own convention says not to chase — folding it in would pull the combined score under the committed threshold. `shared/playback` has no component, scores 92.78% on its own, and was therefore **added to the glob**. So logic slices can keep joining and raising the floor; the unresolved question is narrower than it looked — what to do with a slice whose *component* mutants swamp its logic mutants. The glob is `.ts`-only, so every slice so far had its components excluded without anyone having to decide anything — which is probably the shape of the answer, since a `.tsx` exclusion is exactly "a component-excluding glob". Running totals: `shared/offline` took the combined score to 91.73 (`break` stayed 91); `shared/api-client` scored 98.25% and took it to 93.43 (`break` 91 → 93); `shared/lib` scored 97.35% → 93.72; `shared/telemetry` scored 93.94% over 165 mutants with all ten survivors triaged equivalent → 93.79 over 2,028 mutants; `shared/auth` scored 94.90% and the full 46-file run measured **93.70%** over 2,126 scored mutants. `break` **stays at 93** throughout, because 94 does not clear. **Slice 9 is the first `.tsx` slice and must resolve this**, and it arrives with the threshold at its highest and no worked example — every one of the seven `.ts`-only slices raised the floor while dodging the question. `shared/playlists` (8b) has two components and was expected to be the one that forced it; it did not, for the same reason as the rest — the `.ts`-only glob excluded both `.tsx` files before the question could be asked, so it joined at 94.30% and took the combined figure to **93.87%** over 2,354 mutants, `break` still 93. It does leave slice 9 the one thing its predecessors could not: evidence about the component side. Of 36 hand-authored semantic mutations against its two `.tsx` files, **zero were presentational noise and 31 were killed** — so components are not intrinsically unmeasurable, and the obstacle is the *generated* `StyleSheet`/prop-config mutants a `.tsx` glob would admit, not the components themselves. What slice 9 needs is therefore a threshold that tolerates those, not a cleverer glob.
- **`TrackResponse.featured_artists[].mbid` and `.deezer_id` are typed `T | null` but arrive `undefined`.** Go's `service.FeaturedArtistDTO` declares them `*string`/`*int64` with `json:",omitempty"`, so an unset value **omits the key** rather than sending `null` — while `apps/mobile/src/shared/api-client/types.ts` promises `null`. Any consumer writing `f.mbid === null` is wrong; `??`-style reads are safe either way, and the only two direct consumers (`LibraryRow`, `toPlaybackTrack`) read just `.name`, so nothing is observably broken today. Found by slice 6's contract test looking at the *write* direction of the same wire shape. Belongs to `shared/api-client` (slice 5), so fixing it means amending that slice's record too.
- **`Artwork` treats an empty string as a live image URI.** `shared/ui/primitives/Artwork.tsx` renders `source={uri != null ? { uri } : null}`, so `uri=""` issues a request for an empty URI instead of drawing the placeholder. Slice 6 fixed the one producer it owns (`trackToDiscoveryResult` now collapses `''` to `null`), but the primitive is the general fix and every other producer is still unguarded. Belongs to `shared/ui` (slice 15) — scheduled for Accessibility and Liveness only, so this needs picking up deliberately or it will be missed.
- **The `expo-file-system` double let a load-bearing guard go unconstrained in four slices besides the one that found it.** Slice 7 tightened the double and added two `harness.test.ts` cases; the full suite stayed green, so no slice was leaning on the forgiving behaviour. **But only telemetry's call site now has a test that fails without the guard** — `shared/offline/pinnedFiles.ts`, `shared/offline/pinnedStore.ts`, `features/playback/audioPrefetch.ts` and `shared/ui/theme/themePreference.ts` are merely no longer *unconstrainable*.
- **`supabase.auth.getSession()` can reject, and `shared/api-client` says it cannot.** That slice's `CLAUDE.md` states "`getSession` resolves with `{session: null, error}` — it never throws", and `authorization()` is written to that assumption: it reads the `error` field and has no `try`. But `GoTrueClient.__loadSession` awaits `_removeSession()` inside a `try`/`finally` with **no `catch`**, and `supabaseClient`'s storage adapter deliberately does not swallow a keychain `removeItem` failure — so a keychain fault while discarding an invalid stored session rejects `getSession()`, and `apiFetch` then rejects with a raw `Error` that is neither an `ApiError` nor a `NetworkError` and so is invisible to `isRetryable`. Found by slice 8. Belongs to `shared/api-client` (slice 5).
- **The keychain adapter catches reads but not writes.** `getItem` degrades a throwing `SecureStore.getItemAsync` to `null`; `setItem` and `deleteItemAsync` let a failure propagate into SDK internals. Slice 8 recorded rather than fixed this, on the argument that swallowing a *write* failure trades a loud failure for a silent one on the app's third durability guarantee — but it is a deliberate asymmetry with no test asserting it is deliberate, and it is the mechanism behind the item above. Worth an explicit decision.
- **The banned noun is enforced per slice, so unhardened slices are unchecked — and one is shipping "Songs" to users.** `features/discover/state.ts:44` sets `KIND_LABELS.track` to `['Song', 'Songs']`, and `kindLabel` renders those as the Discover screen's filter chips and section headings — the exact thing `features/library/CLAUDE.md` forbids ("the noun is **Track**, never 'Song' — chip and list vocabulary included") and the root `CLAUDE.md` lists under Always in force. Nothing caught it because the check lives inside each hardened slice's own `slice-invariants.test.ts` and scans only that slice's source; `features/discover` is slice 12 and has no such test yet. Two ways out: keep waiting for slice 12, or lift the scan to one repo-wide test now. The second is a handful of lines and would close the gap for every unhardened slice at once, which is the whole argument for invariant tests being the cheapest durable constraint there is. Found by slice `shared/playlists`.
- **Two optimistic-patch implementations disagree about how many caches a playlist write touches.** `shared/playlists/mutations.ts` patches exactly one family per operation — add bumps `track_count` in `playlistKeys.list` and never the target's detail; remove and rename patch `playlistKeys.detail` and never the matching row in the list. The SSE-side patch for the *same* operations writes both (`shared/events/playlistCachePatch.ts`, 15+18 and 33+43), which is what `shared/events`' own rule to keep `track_count` in agreement requires. So the same action is cache-consistent when another device performs it and briefly inconsistent when this one does, until `onSettled` refetches. Bounded by the refetch and not data loss, but it is one behaviour with two implementations and **no test in the repo crosses them** — neither suite calls the other's code, so they can drift indefinitely without anything going red. Reconciling them touches `shared/events` as much as `shared/playlists`, which is why slice `shared/playlists` recorded it rather than fixing it.
- **Device smoke of the event stream.** The slice-1 SSE fixes (CRLF framing, retry-on-null-token, error logging) and the playlist cache-consistency fixes are verified only by tests written in the same session. Sign in, save a track, watch the row flip, background and foreground, confirm reconnect.
- **Re-measure the complexity ceiling from CI.** The step in `test-mobile.yml` is `continue-on-error` because a locally-derived 137 scored 145 on a depth-1 clone. With `fetch-depth: 0` in place, read the number from a green run, set `MAX`, drop `continue-on-error`.
- **Two gates never executed.** `deploy-backend`'s test dependency needs a `services/go-api/**` push; `release-ios`'s needs a tag. Both are wired and unproven.
- **`react-doctor.yml` stays advisory** and should not be made blocking — it runs `@latest`, and a gate must not change behaviour because upstream shipped a rule. The pinned gate lives in `test-mobile.yml`.
- **`Discovery eval nightly` is red**, pre-existing and unrelated.
- **The Go suite's kill rate is unmeasured.** 268 test files behind a 65% coverage floor — the same profile the mobile suite had when it measured 38%. Two `test-assassin` runs on `internal/acquisition/service` and `internal/catalog/service` would establish whether the backend half of this programme is needed at all. Deliberately deferred; worth doing purely to find out there is no work.

Note the defect is an *equivalent mutation* client-side — the field is sent and ignored, so no mobile mutation and no coverage number could ever have moved. The second path that could have healed it stays cold: `setTrackNumber` has zero callers despite being implemented, unit-tested, and route-registered.
