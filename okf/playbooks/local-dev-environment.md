**`services/go-api/deploy/compose.dev.yml`** is the only local-dev infra file: `postgres:16-alpine` (container `altune-postgres-dev`, user/db `altune`, password `altune_dev`, port 5432, named volume `altune-postgres-data`) and `redis:7-alpine` (container `altune-redis-dev`, port 6379, named volume `altune-redis-data`). Both carry healthchecks (`pg_isready` / `redis-cli ping`, 5s interval, 10 retries). Production runs on a separate Supabase project (ADR-0003), so this file is dev-only. Drive it from the repo root with `npm run dev:up` / `dev:down` / `dev:reset` (the last wipes volumes) rather than retyping the `-f` path.

It pins `name: altune` at the top. That is load-bearing, not decoration: Compose otherwise derives the project name from the compose file's parent directory, so the file's 2026-07-25 move out of the repo root would have renamed the project `altune` → `deploy` and left every running container and both named volumes orphaned under the old project. The pin makes the project identity independent of where the file sits. Its prod sibling pins `name: go-api` for the same reason — that was its directory-derived name before the move, and Caddy's `caddy-data`/`caddy-config` volumes (holding the Let's Encrypt certs) are project-prefixed, so a rename would have silently re-provisioned certificates against Let's Encrypt's rate limit.

**Two files were deleted in that same move.** `services/go-api/docker-compose.yml` was a go-api-plus-infra bundle that had never once been run (no `altune-postgres` container or `go-api_postgres-data` volume has ever existed on the dev machine) and whose header still claimed it was for "production deployment on OCI instance" — three compose files with overlapping service names was the confusion, not a capability anyone used. `scripts/deploy.sh` was the pre-blue-green deploy; it force-removed every `altune-go-api*` container, which under blue-green would have killed both colours at once.

**Hot reload — `.air.toml`**: `air` watches `.go`/`.toml` files (excludes `tmp/`, `vendor/`, `node_modules/`, and `_test.go` files), rebuilds with `go build -o ./tmp/api.exe ./cmd/api`, and restarts `tmp/api.exe` after a 500ms debounce. Per `services/go-api/CLAUDE.md`, plain `go build && ./tmp/api.exe` also works without hot reload; code changes never take effect until rebuild+restart either way.

**Which env file loads.** `config.Load` calls `godotenv.Load(".env.development")` — an explicit filename, not the library default of `.env`, so the dev file's name states its scope the way `.env.production` always did. The load error is discarded: in production no dotenv file exists at all (Compose injects `../.env.production` through `env_file`), and the process gets its config from the real environment. Because the path is relative, it resolves only when the binary runs from `services/go-api` — `./tmp/api.exe` and `air` both do; a `go test ./...` in a package directory does not, which is why config tests set their environment explicitly rather than relying on a file.

**Required env vars (`.env.example`, categories only — no secrets)**: environment/logging/host/port; CORS origins; `DATABASE_URL` (local Postgres or Supabase — session-mode pooler port 5432, NOT transaction-mode 6543); Supabase Auth JWKS config (HS256 unsupported) + `SUPABASE_ANON_KEY`; `REDIS_URL` (optional — caches degrade gracefully absent, see [shared-infra](../backend/shared-infra.md)); a block of discovery-provider API keys (MusicBrainz, Last.fm, Fanart.tv, Genius, Discogs, YouTube — all optional, feature disables when unset); OCI S3 object storage config + local `MUSIC_DIR` fallback; audio-acquisition tool paths (ffmpeg, yt-dlp cookies/JS runtime, see [pipeline](../backend/acquisition/pipeline.md)); Mission Control operator gate (`OPERATOR_USER_ID`, fail-closed — `/admin` denied to everyone until set) + `ALERT_NTFY_URL`; and a block of discovery-telemetry/ranking-experiment flags (`EVAL_METER_ENABLED`, `ALERT_ZERO_RESULT_THRESHOLD`, `BEHAVIORAL_CORPUS_PATH`, `BEHAVIORAL_RANKING_ENABLED`, `EXPLORATION_ENABLED`/`EXPLORATION_RATE`, `TAIL_DEMOTION_ENABLED`, `CROSS_KIND_PROMINENCE_ENABLED`) — most default `false`/empty and are explicitly eval-A/B-gated before flipping on, per inline comments.

**Gotcha**: copy `.env.example` to `.env.development`, not to `.env` — the latter is now ignored by the loader and will look like a silently empty config (every var falling back to its `envDefault`, then failing validation on `SUPABASE_JWT_JWKS_URL`).
