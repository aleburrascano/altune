Independent workflows, each scoped to a path or schedule.

**test-backend.yml** — the baseline gate. Triggers on PRs and pushes to `main` touching `services/go-api/**`. Runs `go vet ./...`, then depguard via `golangci/golangci-lint-action` (pinned v2.12.2 — v2.3.0's binary was built with Go 1.24 and refused to lint once `go.mod` moved to `go 1.25.0`, failing every run at this step until the bump; rules in `services/go-api/.golangci.yml` — domain-purity and shared-never-imports-features, per the structure-audit F1 enforcement), then `go test -race -count=1 -coverprofile=coverage.out ./...` with `CGO_ENABLED=1` on an ubuntu-latest runner (the race detector needs cgo, which the dev box — Windows, no C toolchain — can't provide locally; this is where data races in concurrent telemetry code, e.g. the log ring, event tap, provider store, scheduler counters, alert monitor, are actually caught). A final **coverage ratchet** step reads that profile and fails the job if total statement coverage drops below a hardcoded `MIN` (65, the baseline measured when the step was added). The floor is a regression guard, not a target — raise it after hardening a module, never lower it to make CI green. Coverage alone is a weak signal, so the number is not the quality gate: the `qa-slice` skill gates on whether mutating a covered line turns the suite red. The mobile side has an equivalent ratchet in `apps/mobile/jest.config.js`, now **per-glob** rather than one global average — a single blended number let an uncovered reducer hide behind well-covered UI, which is how `shared/events` reached a 0% mutation kill rate with the global floor satisfied. It is enforced by `test-mobile.yml`, added 2026-07-30; until then nothing in CI executed the mobile suite at all.

**test-mobile.yml** — the mobile counterpart to `test-backend.yml`, and blocking. Triggers on PRs and pushes to `main` touching `apps/mobile/**`. Runs `tsc --noEmit`, then `eslint` (which is where the mobile feature-isolation zones are enforced — the analogue of the backend's depguard rules), then `jest --coverage --ci` against the per-glob floors. It checks out the **whole repo**, not just `apps/mobile`: the cross-surface contract test derives the backend's published event names from `services/go-api` source at test time, so the Go tree must be on disk.

**mutation-mobile.yml** — cron `20 3 * * *` plus manual dispatch, running Stryker (`npm run mutate`, config in `apps/mobile/stryker.config.json`) over the slices listed in `mutate`. This is the gate that answers what coverage cannot: whether the tests *constrain* the code or merely execute it. Scheduled rather than per-PR because a full run mutates hundreds of variants — `test-mobile.yml` is the fast gate, this is the slow truth. The `break` threshold is a ratchet on the same terms as the coverage floors: raise it when a slice is hardened, never lower it to go green. The report is uploaded as an artifact even when the job fails, because the surviving-mutant list is the actionable output and a red run is exactly when you want to read it. Stryker's sandbox lives at the repo root (`../../.stryker-tmp`) deliberately — inside `apps/mobile` it sits under jest's `rootDir` and jest collects the sandbox's own copies of every test file, silently doubling the suite.

**react-doctor.yml** — the only mobile-scoped gate, and advisory (`blocking: warning`). Triggers on PRs and pushes to `main` touching `apps/mobile/**`, running `millionco/react-doctor@v2` with `directory: apps/mobile` against the rule overrides in `apps/mobile/doctor.config.ts`. It spent its whole life until 2026-07-25 at `apps/mobile/.github/workflows/react-doctor.yml`, where GitHub never looked — Actions reads workflows only from the repository-root `.github/workflows/`, so a nested copy is an inert file that reads like live CI. It has therefore never gated anything, which is why it was promoted as advisory rather than blocking: its first real run is expected to surface a backlog.

**discovery-eval-gate.yml** — a narrower quality gate layered on top, scoped only to PRs touching ranking-path files: `service/rank*.go`, `merge*.go`, `diversity*.go`, `pipeline*.go`, `behavioral_signals*.go`, `service/eval/**`, `cmd/discoveryeval/**`. It checks the harness compiles (`go build ./cmd/discoveryeval`) and runs the deterministic rank/merge/eval/behavioral-corpus/replay unit tests (`go test ./internal/discovery/service/... ./internal/discovery/service/eval/...`). It deliberately does NOT run the full positional eval (`cmd/discoveryeval -mode eval`, needs live providers + DB/Redis, see [eval-harness](../backend/discovery/eval-harness.md)) — that stays nightly/on-demand. Exists because a plausible ranking improvement once turned out to be a same-sample regression (per `discovery-eval-harness-program` project memory) — this gate stops a ranking diff merging without deterministic checks passing.

**deploy-backend.yml** — triggers on push to `main` touching `services/go-api/**`, or manual dispatch. `concurrency.group: deploy-backend` with `cancel-in-progress: false` serializes deploys. Steps: warns (doesn't block) if the push touched `services/go-api/migrations/` — schema migrations are applied manually via psql, by design, never by the pipeline; verifies `DEPLOY_HOST`/`DEPLOY_USER`/`DEPLOY_SSH_KEY` secrets are present; SSHes in (`appleboy/ssh-action`) and runs `git pull --ff-only origin main` + `bash deploy/blue-green.sh` on the VM. The script owns the whole swap — build the idle colour, health-gate it before any traffic moves, flip the Caddy upstream, verify publicly, roll back if that fails — so the workflow no longer polls `/health` itself (the gate is now inside the deploy, where it can still act on the result) and no longer hand-clears stale containers (recreates happen on an idle colour, so the name conflict that cleanup existed for cannot arise). On any failure the run prints the `deploy/rollback.sh` command. See [production-deployment](production-deployment.md) for the topology and the blue-green mechanics.

**release-ios.yml** — triggers on a `v*` tag push or manual dispatch with a version input. Builds an **unsigned** iOS `.ipa` on macos-15 (Expo prebuild → CocoaPods → `xcodebuild archive` with `CODE_SIGNING_ALLOWED=NO`) for sideloading via AltStore/SideStore (which re-sign on-device with the user's own Apple ID — no Apple Developer account needed). Publishes a GitHub Release with the `.ipa`, then a second job updates the AltStore manifest (`apps.json`) on a dedicated, unprotected `altstore` branch via `scripts/update-altstore-source.mjs` so existing installs see the new version.

**uptime-check.yml** — cron `*/5 * * * *` (GitHub's minimum granularity) plus manual dispatch. Curls `UPTIME_HEALTH_URL` (a repo Environment secret named "uptime") and, on non-200 or unreachable, pushes an ntfy alert (`UPTIME_NTFY_URL`, optional). Exists because the in-process alert monitor (see [alerting](../backend/admin/alerting.md)) dies with the box and can't report total outage — this runs off-box on GitHub's infrastructure, $0 cost, storing no topology (only the health URL/ntfy URL as secrets).

**Gotcha**: only `test-backend.yml`, `test-mobile.yml` and `discovery-eval-gate.yml` gate PRs. `deploy-backend.yml` fires on push to `main` (post-merge), so a merged PR auto-deploys to production — the only manual step left is applying migrations.

## Acquisition selection gate (2026-07-26)

`test-backend.yml` gained a step after `go test -race`: `go run ./cmd/acquisitioneval -baseline ./cmd/acquisitioneval/baselines.json`. It runs acquisition's real `CoreSteps` pipeline in-process against committed goldens and exits non-zero if overall or per-failure-class accuracy drops more than 1% below the committed baseline. Provider-free and offline — no network, no database — so unlike `discovery-eval-nightly.yml` it can gate every PR rather than run on a schedule. Re-baselining is explicit (`-update-baselines`), and the baseline is a floor, never lowered to make CI green. A duplicate assertion lives in the Go suite (`TestEmbeddedSuiteMatchesCommittedBaseline`) so the same regression fails locally before it reaches CI.
