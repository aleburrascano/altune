## Top 3 by payoff against cost

1. **One error writer that emits RFC 9457 with the correlation id.** Route about 30 bypasses (acquisition handler, eventstream, auth 401s, hand-built bodies, `BadRequestCode`) through HandleServiceError. Add `type/title/status/detail/instance` plus `code`, map Canceled/DeadlineExceeded, log once, and expose `X-Correlation-ID` in CORS.
   Every error, on web and native, then carries what failed, a stable code and a ref that leads to the logs. The change is additive for the client (`parseErrorBody` ignores unknown fields). Deleting `WriteError`/`WritePlainError`/`BadRequest`/`NotFound`/`InternalError` keeps it that way.
2. **Client: one error-to-copy module driven by the code.** Give `ApiError` the code union, `detail`, `retryAfterMs` and the id from the body. `describeError(error, action)` replaces failureCopyForAction and the error-blind `alertOnError(variables)`. Fix the raw "API … returned 409" banner, and attach the id in `reportClientError`.
   A user sees "Favorites are full (max N)" instead of "We could not complete that request". Support can match any report to a server log line.
3. **One goroutine panic guard and one backoff policy in shared Go modules.** `runloop.Try` replaces 12 hand-written `recover()` blocks and the silent `_ = recover()`, enforced by forbidigo. `shared/backoff` (exponential, jitter, cap) replaces five retry loops and the nested ytmusic retry, with idempotent-only retries in egress.
   Small, mechanical diffs. They remove drift (stack and redaction now differ per site) and the 6× retry amplification on provider outages.

Unverified: whether any path today lets `providerhttp.StatusError` reach HandleServiceError; whether web builds report uncaught errors and unhandled rejections at runtime.
