> Rebuild the mobile test suite slice by slice against the twenty-category taxonomy, one slice per run of `/qa-slice`, each finishing with a committed selection record, a raised coverage floor, and a mutation score. **Read the ADR first** — it carries why the programme exists, and the alternatives that were rejected and should not be re-proposed. This file is the ledger: what is done, what is next, and what is outstanding.

## The loop, per slice

`/qa-slice apps/mobile/src/<path>/` runs it. In short: select all twenty categories and commit the verdict *before* writing tests → dispatch blind authors in parallel, one per work unit → verify every finding they report against the source yourself → resolve each as a source fix or an `it.failing()` → run Stryker and `test-assassin` → raise the ratchets → update the nested `CLAUDE.md` and any `okf/` concept the run touched.

Five things that are easy to get wrong, all learned the hard way:

- **Blind means blind.** The one permitted `okf/` file is the taxonomy. A pre-filled selection record is for the orchestrator, never the authors.
- **Harvest before deleting anything.** Findings that live only in a chat transcript are lost at the end of the session. `okf/testing/shared-acquisition.md` exists because eight verified survivors nearly were.
- **Prove each new gate fails when it should.** Apply the mutation by hand, watch the intended test go red, revert. Passing proves nothing.
- **Never run two assassins against one working tree.** They share the suite, so each one runs it while the other has a mutation applied. Survivors stay trustworthy — a concurrent mutation can only add failures — but every *kill* becomes unattributable, and a kill rate is the number this programme reports. Slice 4 discarded both agents' attributions and re-ran all 98 mutations sequentially. Group by source file and run them one at a time.
- **Never leave an unhandled rejection in a test of a fire-and-forget API.** `void enqueueCritical(...)` is fine while the source is correct, but Stryker's `BlockStatement` mutator empties a function body, so `withEnvelope` returned `undefined`, `enqueueCritical` rejected, and the rejection was unhandled — which under Node 25 kills the *worker* rather than failing the test. Stryker abandons the whole run after a handful of child-process crashes, so a mutant that should have been a clean kill aborted the measurement at 32% instead. Attach a `.catch()` to any promise a test deliberately does not await.
- **A source-scanning test must read the canonical file, not `__dirname`.** Stryker runs from a sandbox copy with every mutant switch inlined, so a contract test that regex-matches a source shape (`payload: { … session_id: getSessionId() }`) matches in `jest` and fails the *dry run* under `stryker` — which aborts before a single mutant is applied, and reports it as a config error rather than a test failure. Resolve the repo root once and read `apps/mobile/src/…` from there. Slice 7 lost two Stryker runs to this.
- **Take the verdict from the exit code, not the output.** Slice 4's first gate-proof harness grepped the runner's summary text and reported a gate as biting when it was not; the mutation actually survived. Two mutation results in that run were also silently wrong because a 4-space anchor matched inside a 6-space line elsewhere in the file — the mutation applied to a different call site than the one it was labelled with. Anchor on something unique, and assert the anchor matched.

## Outstanding

- **The backend coverage floor was lowered 65 → 62 on 2026-07-31, and owes a ratchet back.** `test-backend.yml`'s ratchet had been failing for at least eight consecutive runs (62.1% → 62.2% → 62.4%) without blocking anything, because that workflow and `deploy-backend.yml` fired on the same push and ran in **parallel** — the deploy never waited for the verdict. `cb26d1c` (2026-07-30) made the deploy `needs: test`, and the very next backend push, an unrelated audio-versioning fix, was the first thing the floor had ever actually stopped. The floor was lowered to 62 to let that deploy through; the coverage did not move and the code was not at fault. **This is the one lowering on record and it must not become a precedent** — the repo's rule everywhere else is raise-only, and a floor that yields on demand is not a gate. Where the missing 3pp lives, by uncovered-function count: `discovery/adapters` (245), `discovery/service` (85), `catalog/adapters` (77), `acquisition/service` (60). The adapter packages are the bulk and the least testable without a database — `catalog/adapters/persistence/track_repo.go` is 0% end to end — so the cheap wins are in the two `service` packages, which are pure logic behind ports. Ratchet 62 → 65 as those land, and delete this entry when it clears.
- **The per-glob coverage floors are enforced per *file*, not per glob — and the gate is currently red.** A glob key like `'src/shared/events/**'` makes Jest apply the threshold to every matching file individually, not to their aggregate. Slice 1 recorded 97/90/100/100 as though it were an aggregate, and two of its own files sit below that: `sse-client.ts` (96.24% stmts / 85.71% branches) and `trackCachePatch.ts` (94.93% / 78.12%). So `npx jest --coverage --ci` — the exact command in `test-mobile.yml` — has been failing since slice 1 landed, on slice 1's own floor. Confirmed independent of slice 3 by zeroing the playback floor and re-running. Two ways out, both someone's call: bring those two files up to the committed floor, or split the ratchet into per-file entries that record what each file actually holds. **Do not** lower the events numbers to fit — that is what raise-only forbids. Every slice from here should verify its floor per-file before committing it; slice 3's 99/99/100/99 and slice 4's 99/86/100/100 were both checked that way, and slice 4 re-confirmed that these two events files are still the *only* per-file breaches in the repo.
- **`stryker.config.json`'s ceiling is about UI-bearing slices, not about adding slices.** It has one `mutate` glob and one global `thresholds.break`, raise-only. `shared/acquisition` measures 79.44%, dragged down almost entirely by `StyleSheet`/`Animated`-config mutations in its two presentational components, which this repo's own convention says not to chase — folding it in would pull the combined score under the committed threshold, and lowering the threshold to fit is what raise-only forbids. `shared/playback` has no component, scores 92.78% on its own, and was therefore **added to the glob**: combined with `shared/events` it measures 91.69%, and `break` went 90 → 91. So logic slices can keep joining this glob and raising the floor; the unresolved question is narrower than it looked — what to do with a slice whose *component* mutants swamp its logic mutants. Still needs an answer (per-slice configs, a component-excluding glob, or a separate threshold) before slice 9 (`features/detail`). `shared/offline` joined on the same terms and took the combined score 91.69 → **91.73** (events 90.75, playback 92.37, offline 92.71); `break` stayed at **91**, because 92 does not clear. Note what made it eligible: the glob is `.ts`-only, so its one component was excluded without anyone having to decide anything — which is probably the shape of the answer for slice 9, since a `.tsx` exclusion is exactly "a component-excluding glob". `shared/api-client` joined and scored **98.25%**, taking the combined score 91.73 → **93.43**; `break` went **91 → 93**. It has no component at all, so it again did not force the question. `shared/lib` joined and scored **97.35%**, taking the combined score 93.43 → **93.72**; `break` **stays at 93**, because 94 does not clear. It too has no `.tsx`. `shared/telemetry` joined and scored **93.94%** on its own (165 mutants, 155 killed, all ten survivors triaged equivalent); it has no `.tsx`, so it too did not force the question, and combined **93.72 → 93.79** over 2,028 mutants, and `break` **stays at 93**, because 94 does not clear. Measured after the slice landed, hence the two-step: the ledger row was committed with the slice's own score and this figure followed. Worth noting what moved inside it — **`shared/offline` went 92.71 → 93.12 with no test written for it**, because tightening the `expo-file-system` double made the `if (!dir.exists)` guard in `pinnedFiles` and `pinnedStore` constrained rather than merely covered. A harness fix raises every slice that shares the harness. **The question is now overdue and the next slice will not answer it either** — `shared/auth` is also component-free, so `features/detail` (slice 9) is the first slice that must resolve it, and it will arrive with no precedent to lean on. `shared/auth` duly joined on the same `.ts`-only terms and scored **94.90%**; the combined run over all 46 files measured **93.70%** (2,126 scored mutants) and `break` **stays at 93**, because 94 does not clear. That combined number is now measured rather than inferred — it was run in full before the config change was committed, precisely so a red CI gate could not be discovered later. **Slice 9 is now unavoidable**, and note what it inherits: every one of the seven `.ts`-only slices raised the floor while dodging the question, so the first `.tsx` slice arrives with the threshold at its highest and no worked example.
- **`TrackResponse.featured_artists[].mbid` and `.deezer_id` are typed `T | null` but arrive `undefined`.** Go's `service.FeaturedArtistDTO` declares them `*string`/`*int64` with `json:",omitempty"`, so an unset value **omits the key** rather than sending `null` — while `apps/mobile/src/shared/api-client/types.ts` promises `null`. Any consumer writing `f.mbid === null` is wrong; `?? `-style reads are safe either way, and the only two direct consumers (`LibraryRow`, `toPlaybackTrack`) read just `.name`, so nothing is observably broken today. Found by slice 6's contract test looking at the *write* direction of the same wire shape. It belongs to `shared/api-client` (slice 5), so fixing it means amending that slice's record too — deliberately not done inside slice 6.
- **`Artwork` treats an empty string as a live image URI.** `shared/ui/primitives/Artwork.tsx` renders `source={uri != null ? { uri } : null}`, so `uri=""` issues a request for an empty URI instead of drawing the placeholder. Slice 6 fixed the one producer it owns (`trackToDiscoveryResult` now collapses `''` to `null`), but the primitive is the general fix and every other producer is still unguarded. Belongs to `shared/ui` (slice 15) — which is scheduled for Accessibility and Liveness only, so this needs to be picked up deliberately or it will be missed.
- **The `expo-file-system` double let a load-bearing guard go unconstrained in four slices besides the one that found it.** `Directory.create()` throws when the directory already exists unless `idempotent: true`; the double modelled it as an idempotent set-add, so `if (!dir.exists) dir.create(...)` was removable with the suite green everywhere it appears — `shared/offline/pinnedFiles.ts`, `shared/offline/pinnedStore.ts`, `features/playback/audioPrefetch.ts`, `shared/ui/theme/themePreference.ts`, and `shared/telemetry/outboxStore.ts`. Slice 7 tightened the double and added two `harness.test.ts` cases; the full suite stayed green, so no slice was leaning on the forgiving behaviour. **But only telemetry's call site now has a test that fails without the guard** — the other four are merely no longer *unconstrainable*. `shared/offline` is already hardened at 92.71% and this survived it, which is worth remembering when reading any completed slice's kill rate: a double that cannot express a failure hides it from every slice at once, not just the one being measured.
- **`supabase.auth.getSession()` can reject, and `shared/api-client` says it cannot.** That slice's `CLAUDE.md` states "`getSession` resolves with `{session: null, error}` — it never throws", and `authorization()` is written to that assumption: it reads the `error` field and has no `try`. But `GoTrueClient.__loadSession` awaits `_removeSession()` inside a `try`/`finally` with **no `catch`**, and `supabaseClient`'s storage adapter deliberately does not swallow a keychain `removeItem` failure — so a keychain fault while discarding an invalid stored session rejects `getSession()`, and `apiFetch` then rejects with a raw `Error` that is neither an `ApiError` nor a `NetworkError` and so is invisible to `isRetryable`. Found by slice 8 while tracing why its own `.catch` arm mattered. Rare, but it belongs to `shared/api-client` (slice 5), so fixing it means amending that slice's record too — deliberately not done inside slice 8.
- **The keychain adapter catches reads but not writes.** `getItem` degrades a throwing `SecureStore.getItemAsync` to `null`; `setItem` and `deleteItemAsync` let a failure propagate into SDK internals. Slice 8 recorded this rather than fixing it, on the argument that swallowing a *write* failure trades a loud failure for a silent one on the app's third durability guarantee — but it is a deliberate asymmetry with no test asserting it is deliberate, and it is the mechanism behind the item above. Worth an explicit decision.
- **Device smoke of the event stream.** The slice-1 SSE fixes (CRLF framing, retry-on-null-token, error logging) and the playlist cache-consistency fixes are verified only by tests written in the same session. Sign in, save a track, watch the row flip, background and foreground, confirm reconnect.
- **Re-measure the complexity ceiling from CI.** The step in `test-mobile.yml` is `continue-on-error` because a locally-derived 137 scored 145 on a depth-1 clone. With `fetch-depth: 0` in place, read the number from a green run, set `MAX`, drop `continue-on-error`.
- **Two gates never executed.** `deploy-backend`'s test dependency needs a `services/go-api/**` push; `release-ios`'s needs a tag. Both are wired and unproven.
- **`react-doctor.yml` stays advisory** and should not be made blocking — it runs `@latest`, and a gate must not change behaviour because upstream shipped a rule. The pinned gate lives in `test-mobile.yml`.
- **`Discovery eval nightly` is red**, pre-existing and unrelated.
- **The Go suite's kill rate is unmeasured.** 268 test files behind a 65% coverage floor — the same profile the mobile suite had when it measured 38%. Two `test-assassin` runs on `internal/acquisition/service` and `internal/catalog/service` would establish whether the backend half of this programme is needed at all. Deliberately deferred; worth doing purely to find out there is no work.

- Slice 1: nine defects fixed, 186 tests, 0% → 90.75%.
- Slice 2: three defects fixed (a NUL-byte identity-key separator, a banned "songs" noun, a store `remove()` that would have wiped every other track), 106 tests, 0% → 98.83%.
- Slice 3: two defects fixed (`loadQueue` not clamping an empty queue to `currentIndex: -1`; `playFromList` inlining the `'ready'` literal against the slice's own invariant), 224 tests, 0% → 99.11%, 92.78% mutation score, and the first slice to *join* the CI mutation gate rather than sit beside it.
- Slice 5: the harness gained a `fetch` double (`jest/doubles/fetch.js`, installed globally, ten cases in `harness.test.ts`) — without one that honours `AbortSignal`, the deadline and cancellation surface was untestable, the same shape as the `write() {}` hole ADR-0020 was written about. 305 tests, 1.46% → 100/100/100/100, the first slice where the per-file minima and the aggregate coincide. One source defect fixed (`provider` interpolated unencoded into six enrichment paths while `externalId` in the same template was escaped). One **live cross-surface defect** found by the derived contract test and **fixed the same day**: the mobile client sends `track_number` on every save, Go's `CreateTrackRequest` had no such field so `encoding/json` discarded it, and `handleCreateTrack` never mapped it into `AddTrackInput` — **even though `AddTrackInput.TrackNumber` existed and `add_track.go` already assigned it**. So a Track saved from an album context lost its position and the library counted 1..N. Two lines in the Go handler, plus two handler tests proved red against the pre-fix code, and the slice's `it.failing()` promoted to a plain assertion. Note the defect is an *equivalent mutation* client-side — the field is sent and ignored, so no mobile mutation and no coverage number could ever have moved; only a test deriving both sides of the wire from source could see it. The second path that could have healed it stays cold: `setTrackNumber` has zero callers despite `SetTrackNumberService` being implemented, fill-only and unit-tested, and its route registered. Four dead exports surfaced (`getArtistTopTracks`, `getArtistAlbums`, `reorderPlaylistTracks` — whose Go route is live and registered — and `setTrackNumber`). Four proposed `it.failing()` markers were **rejected**: each demanded hardening nobody had committed to, so it could never be promoted, and a permanently-red marker is noise the next person deletes.
- Slice 6: three defects fixed (`formatDuration` not clamping a negative duration, so a negative `duration_seconds` rendered the literal `-1:-5` at the two call sites that guard only against `null`; `featuredArtistsFromExtras` admitting a non-finite `deezer_id`, because `typeof NaN === 'number'`; `trackToDiscoveryResult` using `?? null` on `artwork_url`, so an empty string survived into `image_url` and `Artwork` — which renders `source={uri != null ? { uri } : null}` — issued a request for an empty URI instead of drawing its placeholder). 211 tests, 13.46% → 100/100/100/100, 97.35% mutation score, all three Stryker survivors proven equivalent. **The headline is the vacuous-suspect result.** `query-keys.ts` declares the whole cache topology and had zero references in any test file; 15 semantic mutations against it all died, but **only 4 were caught by the pre-existing `shared/events` suites**, which execute it constantly while constraining nothing about it — both sides of their assertions read the same imported constant, so a mutated key still matches itself. The other 11 name real defects (a dropped `sort` collapsing two sort orders onto one cache entry, `lyrics` dropping `artist`, `albumsPrefix` aliased to `artistsPrefix`). Four `it.failing()` markers were **rejected**: `formatDuration` against `NaN`/`±Infinity` is unreachable — the parameter is typed `number`, JSON carries neither literal, and `trackExtras` already filters non-finite values — so guarding it is error handling for an impossible scenario and the marker could never be promoted. The contrast with the `deezer_id` fix is the rule this slice establishes: **fix where the function's own contract is violated (a validator taking `unknown` must not admit what it cannot validate), reject where only an unreachable input would expose it.** Two dead regions surfaced and deliberately kept: `clearDetailHandoff` has no production caller, but ADR-0017 already accepts that; and the bare-string arm of `featuredArtistsFromExtras` has no producer on either surface, contradicting `okf/mobile/shared-lib.md`'s claim that it tolerates a *legacy* shape — migration `010` was relational from introduction, so no such producer ever existed. The concept doc was corrected. One hazard recorded rather than fixed: `_lastTapped` and `_searchId` are two unpaired module variables, so an `await` inserted between `useSaveTrack`'s two adjacent reads would silently mis-attribute `library_add` telemetry to the previous search; the test asserts the invariant that holds instead of the hazard, so a future atomicity fix keeps the suite green rather than turning it red. `shared/lib` also gained the nested `CLAUDE.md` it never had.
- Slice 8: two defects fixed, both on the boundary between two user identities on one device, and both reachable only because the `Session` type is more trustworthy than the value. **A session carrying no `user` object crashed the hook** — `session?.user.id` stops optional-chaining after `session?`, and the SDK's own `_isValidSession` accepts any stored blob with `access_token`/`refresh_token`/`expires_at` while **never checking `user`**, so a keychain entry from an older version reaches the read and throws a `TypeError` inside the auth callback where nothing catches it; `SettingsScreen.tsx:48` would have thrown on `session.user.email` immediately after. Fixed by treating a user-less session as *no session*. **And a failed `getSession()` wiped the local data of a user the listener had already confirmed** — the `.catch` arm called `apply(null)` unconditionally, which reads as an identity change to signed-out and fires `queryClient.clear()`, `clearSessionExpired()` and `unpinAll()`, deleting the signed-in user's own downloads; it is now guarded on `!seededRef.current`, keeping the splash-screen protection and dropping the wipe. 110 tests, 25.35% → 100/93.33/100/100 aggregate and 100/80/100/100 per file, 94.90% mutation score. One test seam was added to production (`_listenerCountForTest`) because replacing `subscribe`'s cleanup with `return () => {}` left the entire 1,500-test suite green: React's `useSyncExternalStore` listener for an unmounted fiber is a silent no-op, so a leaked listener and a released one were indistinguishable while the module-global `Set` grew a dead closure per mount — the `write() {}` hole of ADR-0020 in a different costume. One `it.failing()` was **rejected**: `useSignOut` has no reentrancy guard, but every consumer already gates it (both call sites disable on `pending`, and `ConfirmDialog` closes before invoking), so the marker could never be promoted. **Two findings generalise.** A survivor showed that moving `queryClient.clear()` *before* `await signOut()` left all nine tests green — every one awaited the whole call and asserted only the settled state, constraining "was cleared at some point" but never "was cleared no earlier than the SDK call resolved"; that reordering is a live multi-tenancy leak, and it added Concurrency/ordering to a file the selection had not assigned it to. And the web-fallback test needed three versions to constrain anything: the first crashed Jest workers so unrelated mutants were scored as errors rather than kills, the second stopped the crashes but made all five condition mutants *survive* because both arms answered `null` for an unwritten key, and only the third — asserting the arms **disagree** — killed them. Coverage counted the arm as covered in all three. **A test that selects a branch does not constrain it.**
- Slice 4: five defects fixed — a transient directory-listing failure that dropped and **persisted** an emptied pinned index (a recoverable error causing durable, silent loss of every download); a re-pin during an in-flight download publishing the superseded bytes as `ready`; `pin`/`pinMany` re-admitting an already-`queued` id and downloading it twice; a JSON array walking through `loadIndex`'s shape guard; and `extFromUrl` returning a bare `"."`. 187 tests, 10.60% → 99.36%, 92.71% mutation score. The `expo-file-system` double gained a `list` failure mode, without which "the directory exists but cannot be listed" was inexpressible — the exact condition the first defect's fix guards. A cross-slice gate was also closed: `shared/events` exercised the `repinIfPinned` call site but never pinned a track first, so deleting the call entirely left that suite green.
