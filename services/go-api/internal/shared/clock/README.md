`clock` owns how code reads the time. A decision that depends on the time takes a `clock.Func` from its composition root and calls it, instead of calling `time.Now` itself, so a test can say what time it is. `time.Now` satisfies `clock.Func`, and `Func.UTC()` reads it in UTC, the form every stored timestamp uses. A required clock is a constructor parameter with no default. A nil clock is refused at construction: with an error where startup can report it (`alerts.Conditions`, `NewAlertMonitor`), with a panic where it is a wiring bug (`NewEventTap`, the search-history services). The housekeeping jobs take the clock positionally and do not check it.

Tests drive a clock with `clocktest.Manual` (`clock/clocktest`), not a hand-rolled fake. New and converted seams declare their clock as `clock.Func`; some option-style seams (the limiter and inspection clocks, `logging.WithClock`) still take `func() time.Time` and are converted as their files come free.

Measuring how long something took (`time.Since`) stays with the standard library; only the question "what time is it" goes through the port.
