Infrastructure: `background` owns how background jobs run on a schedule under leadership, and the one panic guard every goroutine goes through.

`SafeRun` and `RecoverContext` recover a panic and log it once, at ERROR with the caller's context, the stack and the panic value with secrets masked. `SafeRun` also returns it as a `*PanicError` so the caller can decide the outcome; the caller does not log it again.

`Detach` is the one way for work to outlive the request that started it: it keeps the request's values (the correlation id) and runs under its own budget. `DetachCancelable(ctx)` is for work that has no natural budget and ends when its owner calls the returned cancel. `WaitWithin` waits for work until a deadline and says whether it finished. When the deadline wins, the wait keeps running in its own goroutine until it returns, so only pass a wait that does end.

Code outside a `main` package never starts a context of its own: it takes the caller's `ctx` and passes it down, and `Detach` is the exception for work that outlives a request. Two checks in `.golangci.strict.yml` hold this: forbidigo on `context.Background` and `context.TODO`, whose home is the `cmd` and `scripts` main packages, and `contextcheck` for a call that drops the caller's context. `_test.go` files and `*test` packages are out of both.

`Tracker` owns detached request work. `NewTracker(TrackerLimits{MaxInFlight})` bounds it: `LaunchWithin(ctx, label, budget, fn)` runs `fn` under `Detach(ctx, budget)` and the panic guard (`background.task_panic`, with `label`), or, at the cap or once draining, drops it, counts it in `Dropped()`, logs `background.task_dropped` and returns false. Launch only work that may be lost, such as telemetry and caches. `Track` is for in-request work that the caller waits on, and is never dropped. `Drain(ctx)` refuses new launches and waits for everything tracked until ctx ends; one composition root drains it once, before the datastores close.

Production code starts no goroutine with a bare `go` statement: `Go(ctx, event, fn)` runs `fn` in one under the same panic guard (`SafeRun`) and returns a channel that closes when `fn` has returned or its panic is logged. A ruleguard rule in `_rules/goroutines.rules`, run by gocritic in `.golangci.strict.yml`, holds this; this package and `*test` packages are its only exceptions.
