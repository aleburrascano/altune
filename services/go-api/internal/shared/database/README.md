Infrastructure: `database` owns how we talk to Postgres.

- A write that spans more than one statement runs in `InTx`. It commits when the function returns nil, and rolls back when it returns an error or panics.
- `IsTransient` decides whether an error means the database is unavailable right now: a connect that fails, a reset, dropped or already closed connection, a deadline (Go's deadline error is a `net.Error`), or a retryable SQLSTATE. Any failed connect counts, whatever its cause, because `NewPool` proves the settings at boot: a connect that fails later means the server end changed, and a retry may outlast it. A fault that lasts (a certificate the client does not trust) therefore answers 503 on every request instead of failing once, so alert on the rate of transient errors, not on this rule. The exception is a server error at connect, such as a wrong password, which its SQLSTATE decides. A caller's cancel is never transient, and neither is a bug (such as a second statement on a connection whose rows are still open, which pgx calls "conn busy") or a refusal such as a constraint violation.
- `ParseEndpoint` reads a database URL and says which host it names, whether it requires TLS and whether it may fall back to plaintext, so a caller that sets a security policy on the URL needs no driver package.
- `NewAdvisoryLocks` hands out one held connection per `Acquire`: `TryAdvisoryLock`, `Ping` and `AdvisoryUnlock` run on it until `Release` returns it to the pool.
