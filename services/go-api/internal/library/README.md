`library` owns what a user's library holds: tracks, playlists, featured artists and their audio.

It owns the tables `featured_artists`, `orphaned_audio`, `playlist_tracks`, `playlists`, `track_featured_artists`, `track_identity`, `track_metadata_changes`, `tracks`. Only `catalog` should write them, and other modules may read them. `acquisition` changes the status and `failure_reason` of a track only through the ledger port, which `library` implements, and keeps its own job queue and upgrade bookkeeping in its own tables, `acquisition_jobs` and `acquisition_upgrade_state`. Until the old columns are dropped, the `acquisition_*` job columns and `rejected_source_keys` of `tracks` are copies kept in step by triggers for a rollback; nothing reads them but `UpdateFenced`. `version` is no longer bumped by `acquisition`, so catalog's optimistic locking sees only catalog and ledger writes.
